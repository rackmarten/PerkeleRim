## Section layout

One section, `Local\PerkeleRim.Link`, 4,465,536 bytes. Whichever game starts first creates it; it disappears when both have closed.

| Offset | Size | Part | Written by |
|---|---|---|---|
| 0 | 128 | `LinkHeader`: magic, sizes, creator version, one `PeerInfo` per side | creator, then each side its own `PeerInfo` |
| 128 | 128 | `InputSlot` (latest `InputState`) | Skyrim |
| 256 | 128 | `PlayerSlot` (latest `PlayerState`) | MSC |
| 384 | 128 | `VehicleSlot` (latest `VehicleState`) | MSC |
| 512 | 1600 | `VehiclePartsSlot` (latest `VehicleParts`) | MSC |
| 2112 | 5184 | `ItemSlot` (latest `ItemState`) | MSC |
| 7296 | 64 | `HandLayerSlot` (latest `HandLayer`) | MSC |
| 7360 | 1600 | `ActorSlot` (latest `ActorList`) | Skyrim |
| 8960 | 64 + 4 MiB | ring Skyrim → MSC (collision chunks, worldspace changes) | Skyrim produces, MSC consumes |
| 4,203,328 | 64 + 256 KiB | ring MSC → Skyrim (look-at text, later events) | MSC produces, Skyrim consumes |

Layout rules:

- Everything is packed (`#pragma pack(1)` / `StructLayout(Sequential, Pack = 1)`), little-endian and fixed size. C# field names match the header.
- `LinkHeader` is frozen across versions. Any other layout change bumps `kProtocolVersion`.
- The C++ header `static_assert`s every size and offset. The C# tests parse those asserts and the `k*` constants out of the header and check the C# mirror against them, so the two can't drift silently.

## Handshake and liveness

Both sides run the same state machine (`Detached` → `Waiting` → `Up`, or `Disabled`), ticked 10+ times a second. Skyrim ticks it on its own thread at 20 Hz, so it also runs in menus. MSC ticks it from `Update`, so the heartbeat stops whenever MSC's main loop stalls.

1. Create or open the section. A fresh section gets its header filled in and the magic written last; a joining side waits while the magic is still 0.
2. Unknown magic or header size: the link is disabled (`not a PerkeleRim link`).
3. Each side publishes its `PeerInfo` (version, pid), even when the versions differ, so both sides can report a mismatch. If the creator's version, or the peer's, differs from ours, both log `protocol mismatch: ... speaks vN, this ... speaks vM` and stay disabled until restarted.
4. On attach, a side throws away whatever is left in its inbound ring (sent to an earlier instance of itself).
5. Each tick bumps our heartbeat. The link is **up** while the peer's heartbeat keeps moving. The first read only seeds the value, so a crashed peer never looks alive. It goes **down** after 2 s without a heartbeat change (e.g. MSC loading a scene) or at once when the peer detaches cleanly (pid set to 0).

Log lines on both sides: `created shared memory` / `joined shared memory`, `link up: <peer> pid N, protocol vN`, `link down: ...`, `link disabled: ...`. The Skyrim side logs to `PerkeleRim.log` (prefixed `link:`), the MSC side to the MSCLoader console and `output_log.txt` (prefixed `PerkeleRim:`).

## Latest-value slots

Continuous state (`InputState`, `PlayerState`, `VehicleState`, `VehicleParts`, `ItemState`, `HandLayer`, `ActorList`) goes through a seqlock slot, not a queue: the reader only ever wants the newest value, and a queue would add lag. The writer bumps `seq` to odd, writes, then bumps it back to even. The reader retries if `seq` changed or was odd. `seq == 0` means never written. Reads return nothing while the link is down.

## Rings

One single-producer, single-consumer byte ring per direction, for messages that must all arrive (collision chunks, events). `head` (producer) and `tail` (consumer) are monotonic byte counts on separate halves of the ring header. A record is an 8-byte `MessageHeader` (`type`, `size`) plus payload and may wrap around the end. `Send` refuses while the link is down, when the ring is full, or when the message can never fit.

## Models

MSC sends its own meshes and textures and Skyrim builds them in memory: nothing is converted offline or written to disk, so the mod ships none of MSC's assets. A model is a set of active `MeshRenderer`s below one MSC object (for items: see [Items](#items)), as one blob (`ModelHeader` with name and counts; per texture a `ModelTexture` header and RGBA8 pixels, top row first; per submesh a `ModelMesh` header with its path below the object, texture index, `ModelVertex` position/normal/UV and 16-bit triangle indices). Positions are in Skyrim axes and units relative to the object's position and rotation, with its scale applied, front faces counterclockwise seen from the front, UV (0, 0) top left. The blob is cut into `ModelChunk` messages so it fits the 256 KiB ring whatever its size; Skyrim's `Model::Assembler` (`protocol/cpp/model.h`) puts it back together and `Model::Parse` checks every bound. Encoded by `msc/src/Link/Model.cs`.

Materials (v12): after the textures the blob has `materialCount` `ModelMaterial`s and each `ModelMesh` names one (`material`, -1 = opaque, lit, no highlight). A material carries `kMaterialCutout` (alpha below `alphaCutoff` isn't drawn: MSC's Standard cutout mode, the beer case's grid), `kMaterialBlend` (alpha blended), `kMaterialUnlit` (MSC's Unlit/GUI shaders), `kMaterialOverlay` (no depth writes, for the death overlay), a highlight color and glossiness, and an emissive color. MSC bakes its color tint and a metal's darker diffuse into the texture, so the texture is the final diffuse; Skyrim has no reflections for these, so smooth and metal surfaces get only a soft highlight. MSC sends one texture per material.

MSC (`msc/src/Game/ModelSender.cs`) reads textures by drawing them into a RenderTexture and reading that back at the end of a frame into an `ARGB32` texture (MSC's textures have no CPU copy, and Unity 5.0's `ReadPixels` refuses `RGBA32`); larger than 1024 is halved. Skyrim (`skse/src/model/ModelView.cpp`) makes D3D11 vertex and index buffers and a mipmapped texture itself, wraps them in a `BSTriShape` cloned from a vanilla mesh and a `BSLightingShaderProperty` with Skyrim's flat default normal map, under one `NiNode` in the player's scene node, so the world lights it. The beer case with its bottles (25 submeshes, 1794 vertices, two 512 x 512 textures) builds in about 5 ms with no measurable frame cost.

A model's id (`ModelChunk.model`, never 0) stands for what it is made of: MSC keys it by the meshes and textures (by name, size and bounds, since every spawned copy of an item has its own mesh instance) and their placement, so identical items share one id and one model. MSC sends each model once per link session and everything again after the link comes back up; its ids start at a random base, so a restarted MSC never reuses an id a running Skyrim still has. Skyrim keeps every model it got by id (a resend replaces it) and builds a fresh node from it per item. Hand-built textures, the temporary materials and item nodes are never freed: the game's destructors expect objects it built itself, so item nodes are kept per model and reused. Spike command `textures <name>` reads any object's model and logs it without sending it.

## Items

`ItemState` (MSC → Skyrim, latest-value slot): MSC's frame, the anchor `generation`, `count` and up to `kItemCapacity` (128) `ItemPose`s, closest to the player first: MSC's item `id` (stable while the item exists, never 0), the `model` id of its look (0 = nothing to draw), `flags` (`kItemVisible` while MSC draws it, `kItemHeld` while it is in the player's hands) and its root's position and rotation (quaternion) in Skyrim space. An item missing from one frame to the next is gone. Only written with items while MSC has the player on the current island; otherwise `count` is 0.

MSC side (`msc/src/Game/ItemLink.cs`): every 0.5 s it looks for `Rigidbody` objects within 15 m of the player's feet (kept until 50 m, so a thrown bottle stays drawn all the way) that are MSC items: named `...(itemx)` or under `ITEMS`, or any non-kinematic loose rigidbody up to 30 kg that isn't part of the player or of something 100 kg or heavier (a thrown bottle; not the van's doors). Each item is split: its root's own renderers are one entry, and each direct child with renderers is an entry of its own, posed on its own. A beer case's bottles are its children, so a drunk bottle simply disappears, and all bottles share one model. Poses go out every frame; a destroyed piece drops out the same frame. When a new anchor moves the island under the player (the next handover, a load door), the items are moved by the same offset so each stays where it was in Skyrim's world, as long as that is within 50 m of the player; the rest stay behind. MSC itself does all the handling (picking up, carrying, dropping, throwing, drinking); mouse and keys already reach it. Spike command `items` logs every entry with its path and model id.

Skyrim side (`skse/src/item/ItemView.cpp`): one node per item id, made by `ModelView::Instance` once its model has arrived, hung under the player's parent scene node like the van (no reference, no collision), posed every frame and app-culled while not visible. Items that go away, change model, or all of them on F10 or an anchor change go back to a per-model pool for reuse.

## Hand layer

MSC's first-person view (the hands, a bottle being drunk, tools in hand, gestures) is not rebuilt in Skyrim: MSC draws it and Skyrim lays the picture over its own frame. MSC already draws all of it with its own `HandCamera` (layer `Player`, over the world camera), so that camera's output is the layer.

`HandLayer` (MSC → Skyrim, latest-value slot): MSC's copy counter (`frame`), `flags` (`kHandLayerValid` while MSC draws into the texture every frame), `texture` (a legacy DXGI shared handle, `IDXGIResource::GetSharedHandle`), `width`, `height`, `format` (`DXGI_FORMAT`) and `costMicros` (MSC's CPU time for the layer, last frame). The texture is transparent where nothing is drawn and lives on the GPU both games use; only the handle goes through shared memory. `InputState.screenWidth`/`screenHeight` (Skyrim's back buffer) tell MSC the size to render at.

MSC side (`msc/src/Game/HandLayerSender.cs`, `SharedTexture.cs`): a hidden camera below `HandCamera` copies its settings every frame and renders into a render texture of Skyrim's screen size, cleared to transparent black. Right after it rendered, the texture is copied into a shared D3D11 texture and the context flushed (COM calls through vtable slots, no native DLL). That needs Unity's renderer on the main thread, so MSC must run with `-force-gfx-direct` (`scripts/launch-msc.ps1` passes it); without it the layer stays off and MSC logs why. A few first-person objects below `FPSCamera` sit on layer `Default` (the piss stream, sauna water, digging bar, tow rope) and are moved to `Player` while the layer is on; changing their layer only around the hidden camera's render doesn't work, Unity culls with the layer an object had when the frame started. Only for the hidden render (`OnPreCull` to `OnPostRender`, restored after, so MSC's own view is unchanged): the layer is lit neutrally (flat ambient 0.5, fog off, MSC's lights masked off layer `Player`, one directional light of its own at 0.8 from above left), so it looks the same at any MSC hour; the strays' `Particles/Alpha Blended` materials are swapped for copies with a runtime-built shader that also writes alpha (Unity's legacy particle shaders write `ColorMask RGB`, which left the piss stream invisible in Skyrim); and the far clip is at least 20 m (`HandCamera` stops at 5 m). Spike commands: `hands` (cameras, layers, first-person renderers), `handlayer on|off|tint|save`, `handlayer light <ambient> <sun>` (the neutral lighting).

Skyrim side (`skse/src/hands/HandView.cpp`, `skse/src/hud/Hud.cpp`): opens the handle with `OpenSharedResource`, wraps the texture in a hand-built `NiSourceTexture` (`ModelView::Wrap`) and registers it with Scaleform's image loader as `img://PerkeleRimHands<n>` (a new name per handle). A clip at the lowest depth of the HUD movie (created through ActionScript; `GFxValue::CreateEmptyMovieClip` takes a negative depth as "next highest") loads it and scales it over the visible frame, flipped vertically since Unity renders into textures bottom row first. So the hands sit under every HUD element and vanish with the HUD in menus. The clip is tinted with Skyrim's light at the player (`HandView::Light`, an AS2 `Color.setTransform` multiplier): outdoors the sky's ambient plus half its sunlight, indoors the cell's (or its lighting template's) ambient plus half its directional color, scaled so a clear noon is 1, hue kept, never below 0.12. Nothing is copied per frame on Skyrim's side; the layer hides when MSC's copy counter stops for 0.25 s.

Cost at 1920x1080 (2026-10-10): about 0.3 ms of MSC CPU per frame, MSC at 8.4 ms per frame, Skyrim unchanged at 16.5 ms (vsync). Known gaps: the hands are lit by MSC's sun and clock, and MSC's particle shaders write no alpha, so the piss stream is in the texture's colors but transparent in Skyrim.

## Damage and death

Skyrim's health is the only one. While Skyrim has handed the player over, MSC never lets its player die: a Harmony prefix on PlayMaker's `Fsm.ProcessEvent` drops MSC's `DEATH` event (vehicle crashes send it), a prefix on PlayMaker's `ActivateGameObject.OnEnter` skips turning on `Systems/Death` (the need deaths in `Database/PlayerDatabase :: Simulation`, drowning, wasps, the train; it must never start, `Activate Dead Body` destroys the player's `CharacterController`, `CharacterMotor` and `FPSInputController` in its first frame), a need death's dead-end state in `Simulation` (`State 6`/`7`/`9`/`10`, `Burn`) is sent on to `Loop` so MSC's needs keep ticking (the need is at 0 by then), a watchdog switches `Systems/Death` off again if anything else turned it on, and each vehicle's `DriverHeadPivot` keeps its seat: the `ConfigurableJoint` it hangs by is held unbreakable while handed over, renewed every frame since MSC sets the van's to break at 300 every frame, and seats whose vehicle wakes up later are picked up within 2 s (a hard hit broke it, and its `Death` FSM threw the driver out through the windshield as a free body that fell through the world or shook the camera), and the pivots below it are put back if anything else moves them more than 1 m. Each such death goes to Skyrim as `PlayerDamage` and costs half of Skyrim's max health (`Damage::Crash`, `protocol/cpp/damage.h`). Skyrim's own fall damage doesn't run while MSC places the player, so Skyrim follows MSC's feet height and `kPlayerGrounded` (`PlayerState.flags`) and applies the vanilla formula (`((height - fJumpFallHeightMin) * fJumpFallHeightMult) ^ fJumpFallHeightExponent`) when the player lands. A hit that kills, or a death in Skyrim combat, makes Skyrim take the player back, send `PlayerDeath` (MSC plays one of its `Death` group clips on its listener), show MSC's blood (`player_blood_vision`, sent ahead as the overlay model `PlayerBlood`) in front of the camera, and kill the player the normal way, ragdoll and reload included. MSC's player stays alive. Known gap: only crashes MSC itself counts as fatal hurt Skyrim; hard but survivable hits do nothing yet.

Healing: what MSC's player consumes heals a share of Skyrim's max health, never past it (`Damage::Heal`): beer 10%, a shot 10%, kilju 15%, a bottle of booze 20%, spirit 25%, a cigarette 5%, food 25%. Milk, juice and coffee heal nothing. MSC (`msc/src/Game/ConsumeWatch.cs`, rules in `msc/src/Link/Consumption.cs`) watches PlayMaker's state changes through a Harmony prefix on `Fsm.SwitchState` while handed over and sends one `Consumed` per finished one: a drink when the player's `Drink` FSM leaves its drinking animation for throwing the bottle or glass (`Drink anim` → `Throw bottle` beer, `Drink anim 1` → `Throw bottle 1` booze, `Drink anim 2` → `Throw glass` shot, `Drink anim 8` → `Throw bottle 2` spirit, `Kilju` → `Calc`); a cigarette when `PlayerFunctions` finds one in the pack and lights it (`Check tobacco` → `Activate`); food when an item's `Use` FSM goes from eating to `Destroy` (`Eat`, `Eat 2`, a single sausage's `Fresh` or `Grilled`), unless the item is a bottle (its `Use` FSM has a `Check drink` state; the `Drink` FSM counts those). Log lines: `consume: <object> :: <fsm> <from> -> <to>, kind K` in MSC's log, `death: MSC's <kind> heals H health of N (max M)` in `PerkeleRim.log`.

## Combat

`ActorList` (Skyrim → MSC, latest-value slot, written every frame while MSC has the player): Skyrim's frame, the anchor `generation`, `count` and up to `kActorCapacity` (32) `ActorPose`s, closest first: the actor reference's form `id`, its feet `position`, `heading` and `velocity` in Skyrim space, the capsule it stands for (`radius`, `height`, units) and its `mass` (kg, a guess from its bounds times its scale at a person's density, `Damage::Mass`; every dragon at least 2000). Only living actors that stand are listed: not dead, disabled, knocked down, ragdolled or riding; an actor missing from one list to the next has gone. Skyrim (`skse/src/combat/Combat.cpp`) takes the high-process actors within 2800 units (40 m) and sizes each capsule from its bounds times its scale (half the narrower side, the full height; a person when the bounds look wrong), logged once per actor. On release it writes an empty list.

MSC side (`msc/src/Game/ActorLink.cs`, math in `msc/src/Link/Actors.cs`): one kinematic `CapsuleCollider` per listed actor of the current generation, carried on by its velocity for up to 0.25 s between lists, on an unused layer that collides only with the player's layer; actors of 250 kg or more (bears, cows, horses, giants, dragons) on a second one that collides with everything but the capsules. The walking player bumps into people; vehicles, their wheels, items and MSC's raycasts with layer masks pass through (vehicles run people over instead, see below). All capsules go when MSC stops playing.

MSC's punch is its own: the Hit key (H) throws MSC's fist animation. Left click does too while the hands are free (`msc/src/Link/PunchButton.cs`): decided when it goes down, with no MSC prompt for what the crosshair is on (globals `GUIinteraction`, `GUIuse`), nothing in the hands (`PlayerHandLeft`/`Right`) and not in a vehicle, the click reaches MSC as its Hit key until let go; otherwise it stays MSC's click. MSC's hand icon flickers on and off while the crosshair is on an item, so a prompt seen in the last 0.5 s still keeps the click. MSC's own bindings are untouched. 0.15 s after the key (the fist is out), MSC sweeps a 0.15 m fist 1.2 m out of its camera against the capsules (`Actors.Punch`) and sends a `PunchEvent` for the first one it touches. No punches while seated in a vehicle. Skyrim checks the actor still stands within 400 units, then casts two of PerkeleRim.esp's spells from the player at it with the player as the one to blame: `PerkeleRimPunch` (damage health, magnitude set per cast to `Damage::Punch`: a quarter of the target's max health, a dragon a quarter of that) and `PerkeleRimPunchStagger` (stagger 0.5). Being the player's hostile spells, the target fights back and a hit on someone peaceful counts as assault, as Skyrim treats any attack. Fun over RPG: no skill, perk or level enters the damage. Drinking pays off in a fight, since MSC's drunk camera makes aiming harder: each MSC drunk level (`PlayerState.needs[kNeedDrunk]`) adds a quarter to the punch, up to twice the sober one at drunk 4 (`Damage::DrunkPunch`).

Blocking is Skyrim's own (`msc/src/Link/BlockButton.cs`, Skyrim side `Combat::Guard`): holding the right mouse button with the hands free (decided when it goes down, the same rule and 0.5 s prompt grace as the punch's left click) reaches MSC as its Watch key (U) until let go, so `PlayerFunctions` raises the left arm to the watch (`Watch ON 2` while held) and lowers it on release; left click and the Hit key are dropped meanwhile, so no punches while guarding. With an item in hand the right click stays MSC's throw; U is still MSC's watch. MSC sets `kPlayerBlocking` in `PlayerState.flags` while guarding, not a ring message, so a lost message can't leave Skyrim blocking. Skyrim keeps the player's hands drawn while MSC has it (Skyrim only blocks with them out: fists, or whatever is equipped; not while a menu such as dialogue has the input), with its first-person model culled so they don't show over MSC's hands, and, while the flag is set, on foot and with no menu up, sets `wantBlocking`, sends the graph `blockStart` (`blockStop` when it clears) and sets the graph variable `IsBlocking` on both graphs (third and first person), putting it back whenever it no longer matches. The graph refuses `blockStart` while MSC has the player (it never sees the hands drawn, `iState` stays 0), so there is no block animation, but Skyrim's hit code only reads `IsBlocking`: hits count as blocked (`TESHitEvent` `kHitBlocked`) and the Block skill, its perks, stagger and power attacks apply as in vanilla. Handback, death and the link going down end the block, sheathe hands Skyrim drew and show the first-person model again.

Thrown items (rules in `msc/src/Link/Throwing.cs`): an item that leaves the player's hand within 0.5 s of the right mouse button (MSC's throw; a drop doesn't count) is followed for up to 4 s, until it's picked up again or hits. Bottles (names with "bottle", booze, spirit) fly twice as fast as MSC throws them, the first time their throw speed shows within 0.3 s: a ranged attack that reaches dragons. Each frame, while it's still at 2 m/s or more, its path since the last frame is swept with a 0.1 m radius against the capsules (`Throwing.Sweep`); on the first one it passes through MSC sends an `ImpactEvent` (`kImpactThrown`, its speed) and turns the item back at 0.3 of its speed, since capsules don't collide with items. Thrown items switch to continuous collision, so a fast bottle doesn't pass through the island's thin ground. Skyrim hits the actor with the punch spells, the damage by speed (`Damage::Thrown`): nothing at 2 m/s, rising to a sober punch at 15 m/s and more. No drunk bonus.

Piss is poison: while MSC's stream object (`PLAYER/.../FPSCamera/Piss/Fluid`) is active, MSC reads up to 64 of its particles per frame and a drop within 0.05 m of a capsule hits that actor; with no particle system to read, the stream is a 1.2 s arc from `Fluid` along the camera at 3.5 m/s. Each actor gets an `ImpactEvent` (`kImpactPiss`) every 0.5 s at most while the stream stays on it. Skyrim casts PerkeleRim.esp's `PerkeleRimPiss` (0x90E, damage health per second, poison resistance applies, 5 s) with the magnitude set per cast to `Damage::PissPerSecond`: 2% of the target's max health per second, a dragon a quarter of that. Recasts refresh it, so the poison runs on 5 s after the stream leaves. Like the punch, it's the player's hostile spell, so it counts as assault. Running people over (rules in `msc/src/Link/RunOver.cs`): light capsules (under 250 kg) don't collide with vehicles, so the van carries on through a person and `CrashMeter` never sees it (the driver loses no health). Instead, while the player drives at 2 m/s or more, the vehicle's box (its own non-trigger colliders' bounds in its space, measured once per vehicle and logged) is checked against every capsule each frame (`RunOver.Touches`); a touched actor gets an `ImpactEvent` (`kImpactVehicle`, the vehicle's speed and way), once per 2 s at most per actor, since the list lags behind the knockdown. Heavy capsules are solid instead: the vehicle stops on them as on a wall (a crash `CrashMeter` counts for the driver), and the hit goes out at the vehicle's speed from the frame before. Skyrim knocks the actor over first (`AIProcess::KnockExplosion` from 100 units behind it along the vehicle's way, magnitude `Damage::KnockOver` = 0.5 per m/s, 1 to 15), then casts `PerkeleRimPunch` with `Damage::RunOver`: nothing below 2 m/s (about 7 km/h), rising linearly to the target's whole max health at 50 km/h, twice its max health from there on (lethal), a dragon a quarter of that. No stagger spell, the knockdown does that. By weight (`Damage::BulkOf`): a light actor's ragdoll is then thrown (once it is a ragdoll, up to 30 frames, for 3 frames every rigid body's velocity is set to 1.2 times the vehicle's speed along its way plus 0.35 of it upward; the vehicle has no collision in Skyrim, so without it the body just drops through the van); a heavy one is only knocked over; a huge one (2000 kg or more, every dragon) isn't knocked over at all, it only takes the damage.

All three kinds are checked against the actor still standing within the listed range (plus 400 units).

Shouts are Skyrim's own (`Combat::Shouts`, rule in `protocol/cpp/shout.h`): Z reaches Skyrim's shout handler as usual, so the equipped shout fires with Skyrim's words, cooldown and Dragon Souls, aimed along MSC's camera (PlayerSync turns the player to it every frame). The player's shout voice is dialogue: every line of the shout topics (Skyrim.esm quest 013E06, `Fus!`, `Ro Dah!`, `Yol!`, ..., VoicePowerStart/End subtypes, picked by voice type lists the player's voices are in). PerkeleRim.esp puts "not the player (`GetIsID` 0x7 == 0) OR `PerkeleRimMuteVoice` (0x90F) == 0" in front of each line's conditions, and Skyrim sets that global to 1 while MSC has the player, so Skyrim's shout voice stays silent for the player only (NPCs and dragons keep theirs; the shout's thunder and push sounds still play). Back to 0 at release and at data load. Skyrim notices a shout as a jump of at least 0.5 s in the player's shout recovery time (which otherwise only counts down; a cooldown already running at the handover doesn't count) and sends `PlayerShout`. MSC (`msc/src/Game/PlayerVoice.cs`, pick in `msc/src/Link/ShoutLine.cs`) plays, for Unrelenting Force, mostly `swear09` (the player's swear subtitled "God of thunder!", what perkele means; MSC's level data subtitles `swear01`..`swear16` with a 16-line table, kept in `ShoutLine.SwearLines`) and a quarter of the time `Human_Perkele`; for any other shout one of `Human_Saatana`, `Human_Vittu`, `Human_Kyrpa` (MSC's `Pieno-soundbank` of `Human_` clips also snores, burps and sneezes, so the swears are listed). Played on the listener in 2D. V is MSC's middle finger only (gesture and swearing line, no shout); swearing (middle click or N) stays MSC's own.

Grunts are dialogue too (Skyrim plays them from the player's voice type folder without a topic event), muted the same way with the same global, whatever the player's race and voice: PerkeleRim.esp gates every line of the topics whose subtype code (`SNAM`) is `HIT_` ("Agh!", "Oof!", "Nargh!"), `BLOC` ("Gah!", "Unf!"), `ATCK`, `POAT`, `BASH`, `DETH` ("Agh...", "Ugh..."), `BLED` or one of the player's breaths (`BREA`, `OUTB`, `ENBZ`, `EXBZ`, `GRNT`, `LWBS`), whichever quest they're in; NPCs and creatures keep theirs. Mutagen's subtype enum doesn't match what these topics hold (it calls the hit topic 013EBB `FlyingMountRejectTarget`), so esp-gen goes by the code. Shout and grunt lines are taken as the last official master has them (Update.esm and the DLCs edit some and add more, the DLC shouts' lines included), so PerkeleRim.esp has Skyrim.esm, Update.esm, Dawnguard.esm and Dragonborn.esm as masters. MSC grunts and swears instead on `PlayerHurt`: Skyrim sends it for every hit event on the player by another actor (`kHurtBlocked` when the guard took it), for each fall and crash after taking its damage off (`Death`; a lethal one sends `PlayerDeath` instead), and once when health first drops below a quarter of max (`protocol/cpp/hurt.h`: again only after healing above half; already low at the handover doesn't count). MSC (`PlayerVoice`, rules in `msc/src/Link/HurtLine.cs`) mostly grunts in a fight and mostly swears out of one: a hit grunts (one of the player's `ouch1`..`ouch10`) and swears one time in five, a blocked hit swears 60% of the time, a fall or crash swears 60% of the time and always when it cost a fifth of max health or more, and low health always swears (the player's `swear01`..`swear16` and `Human_Saatana`/`Vittu`/`Kyrpa`, not the "God of thunder!" Perkele, which stays the shout's). After each sound it stays quiet for 1.5 s; a low health swear during that waits for the end of it (up to 3 s) rather than being dropped. MSC's own stress swearing stays.

Log lines: `actors: capsules on layer N ...`, `actors: punch landed on <id> at D m` / `punch hit nobody`, `actors: <item> thrown [at S m/s (a bottle ...)]`, `actors: <item> hit <id> at S m/s`, `actors: piss on <id>`, `actors: no piss particles to read ...`, `voice: N MSC voice clips, G grunts (...); Perkeles: ...` (first use), `voice: the player yells|grunts|swears <clip> ["<line>"] (<why>)`, `hurt: quiet for <why> (cooldown)` in MSC's log; `combat: voice mute global found|missing` (at data load), `combat: Skyrim's shouts and grunts muted for the player` / `... are the player's again`, `death: the player's health dropped low`, `combat: the player shouted <name> (<id>, N words)`, `combat: drawing the player's hands for MSC's guard`, `combat: the player starts|stops blocking`, `combat: the player's throw at S m/s hit <name> for D ...`, `combat: the player pissed on <name>, poison P/s ...`, `combat: <name> (<id>) as a capsule r R h H ...`, `combat: the player punched <name> for D of M max health (drunk L)`, and while handed over `combat: <name> hit the player with <weapon>[, blocked]` and once a second `combat: <name> fights the player at D units, attack state ...` in `PerkeleRim.log`.

## The pocket

Skyrim's inventory is the pocket for MSC's beer, empty bottles, food and cigarettes: PerkeleRim.esp misc items (`tools/esp-gen`, ids 0x906 + kind: MSC Beer, Empty Bottle, Sausages, Pizza, Potato Chips, Macaron Box, Cigarette), so they come along through load doors, weigh something, sell and live in Skyrim's saves. Nothing can be eaten or drunk on Skyrim's side. Skyrim's counts are the truth; MSC (`msc/src/Game/PocketLink.cs`, rules in `msc/src/Link/Pocket.cs`) adds the changes it sent that Skyrim hasn't applied yet (`seq` above `appliedSeq`), so a second key press before Skyrim answers already sees the first.

While MSC has the player, Skyrim's keys Y and 3 to 8 are PerkeleRim's and never reach MSC; 1 and 2 stay MSC's (hands, tools). In a vehicle only 3 and 5 to 8 work (beer and food, `Pocket.WorksInVehicle`), so the player can drink and eat while driving; nothing goes in or out of the hand there:
- Y puts what MSC's hand carries in the pocket, or, with empty hands, what the crosshair is on (MSC's own pick-up check: 1 m, item layers 19/15/9): one bottle of a beer case (the case is thrown away with its last bottle), an empty bottle (`empty bottle(Clone)`, what MSC throws after a beer), sausages, pizza, potato chips or a macaron box (not spoiled ones). Food goes the way of MSC's garbage (its `Use` FSM's `GARBAGE`), so MSC's save never brings it back.
- Keys 3 to 8, in fixed order: 3 beer, 4 empty bottle, 5 sausages, 6 pizza, 7 potato chips, 8 macaron box. Beer and food are used at once: a beer is MSC's own beer drinking (`DRINKBEER`, as a beer case sends it: the animation, the needs, then the empty bottle; the one MSC throws, a new copy of `BottleBeerFly` that turns up within 10 s, is destroyed and goes into the pocket as an Empty Bottle instead, ready to take out with 4 and throw. A beer drunk from a held case keeps MSC's toss), not while the left hand is busy or a helmet is on; food is a new item from the store's spawner, hidden, put in its `Use` FSM's `Eat` state as soon as it has loaded (the sounds, the needs, then gone). Smoking doesn't stop either, as in MSC.
- 4 takes an empty bottle out into the hand (a copy of MSC's `BottleBeerFly`), which MSC's hand takes the way a click would (`1Hand_Assemble/Hand :: PickUp`: `RaycastHitObject`, then `FINISHED`). 4 again puts it back; with something else in hand that goes in the pocket, that goes in first (a case with more than one bottle is put down instead), anything else is dropped first.
- A slot with none left does nothing.

Left click punches only when nothing MSC would pick up is under the crosshair (the same check), so items without a prompt, like empty bottles, are picked up again.

Cigarettes aren't held: MSC smokes them with I from its global `PlayerCigarettes`, which stays equal to Skyrim's Cigarette count while the link is up. When the link comes up MSC's count wins (Skyrim has none of MSC's cigarettes the first time); after that a change on either side (smoking, a pack bought or picked up in MSC; dropping, selling or picking up in Skyrim, loading a Skyrim save) is copied to the other. MSC's snapshot in a Skyrim save leaves `PlayerCigarettes` out for that reason.

Mead and ale the player picks up in Skyrim (`PerkeleRimBeerDrinks`, quest meads left out) become as much MSC Beer at once, link or not.

Skyrim's HUD shows the pocket while MSC has the player: one line per kind it has, right of the needs bars (`3  Beer  x6`, `I  Cigarettes  x20`).

Test loop: with `PerkeleRim_testbeer.txt` in MSC's folder, every handover tops the pocket up to 6 beer, 10 empty bottles (to throw), 2 sausages, 1 pizza and 20 cigarettes.

Log lines: `pocket: ...` in both games' logs (`counts to MSC`, `+1 MSC Beer` in `PerkeleRim.log`; `a beer pocketed`, `drinking a beer`, `ate ...`, `... in the hand`, `cigarettes ... to Skyrim` in MSC's). Spike commands: `pocket <Y|3..8>` presses a key, `hold <kind>` puts a new item of a kind in the hand without touching the pocket.

## Saves

Every Skyrim save (manual, quick, auto) also keeps MSC's state. This isn't MSC's own save: broadcasting MSC's `SAVEGAME` mid-game makes its FSMs act as if quitting (Satsuma kinematic, items reset, driver unseated) and stalls MSC for 4 to 16 s, and its reload takes about 17 s through the main menu. Instead MSC captures what it can put back in place, from memory, in a few ms. MSC's real save still happens when MSC quits.

On `kSaveGame` Skyrim picks a new random key, sends `MscSave` with `Saves/PerkeleRim/<save name>`, and keeps the key, the save name and whether MSC had the player in its cosave (record `MSCS`). MSC (`msc/src/Game/SaveSync.cs`) writes `PerkeleRim_snapshot.txt` into that folder (`msc/src/Link/Snapshot.cs`: tab-separated text, written as `.tmp` and renamed): the key, a list of PlayMaker globals (needs, drunk, weight, money and fines, cigarettes, day and hour), MSC's time of day (the sun's 2-hour state `MAP/SUN/Pivot/SUN :: Color`, the clock's hour state `:: Clock`, their minutes and the sun pivot's `Rotation`), and, while MSC has the player, both vehicles (pose, velocity, fuel, whether the player sat in it) and the items `ItemLink` tracks near the player (pose, velocity, a beer case's bottle count; items in the player's hands come along with the player). Positions are Skyrim world units, so they survive a new island anchor; rotations and velocities are Unity's (the island only moves, never turns).

Loading a Skyrim save releases the player first. With a key in the cosave, Skyrim sends `MscLoad` after the load (`kPostLoadGame`; also the reload after a death). When the folder's key matches, MSC puts the globals and time of day back right away (states entered as a transition would, so the current hour runs its full length again). A save taken while MSC had the player gets Skyrim's controls back (saves taken by versions that turned them off keep them off) and then hands the player over again once its cell is attached (`PlayerSync::ResumeHandover`; F10 before that cancels it, 30 s timeout). MSC keeps the vehicles and items until the player stands on that handover's island (30 s at most), then puts them back where they were instead of parking them next to the player; without ground there yet they are held, as when driving off the streamed area. Items are found by Unity instance id, so only within the MSC session that took the snapshot; used-up items stay gone, except beer bottles, which go back into their case. Whether the player sat in a vehicle isn't changed. A load that comes before MSC is back in its game (both games just started) waits for it, up to 3 minutes, and is applied 3 s after MSC's player shows up, so MSC's own save loading doesn't overwrite it. A save without a key (older saves, or MSC wasn't linked) or without a snapshot file leaves MSC as it is.

On every save, Skyrim removes snapshot folders whose save is gone, looking for `<name>.ess` anywhere under `Saves` (save managers keep subfolders per character), but not the one being written, nor folders changed in the last 5 minutes (`MscSave::Prune`, `protocol/cpp/msc_save.h`).

## Collision chunks

Chunks are `kCollisionChunkUnits` (2048 units, about 29 m) squares on a grid anchored at world (0, 0); chunk `(x, y)` starts at `(x * 2048, y * 2048)`. A payload is the header, `vertexCount` vertices (`float[3]`, Skyrim units relative to `origin`) and `indexCount` triangle indices, then `roadCount` road triangles (`float[6]`: x, y of three corners, Skyrim units relative to `origin`, either winding). Triangles wind counterclockwise seen from outside in Skyrim (from above for the land); MSC swaps two corners per triangle because the Y/Z swap flips the handedness. A chunk with the same x/y and generation replaces the older one; chunks for another generation are dropped. A chunk has at most 65,000 vertices (Unity 5 meshes index with 16 bits); static triangles past that are left out and logged.

Skyrim side (`skse/src/collision/CollisionSampler.cpp`, `StaticMeshes.cpp`, geometry in `protocol/cpp/collision.h`): while MSC owns the player, each chunk is three parts in one payload.

- **Land**: a heightfield of 33 x 33 samples (64 units apart) from top-down Havok raycasts that keep only the landscape (the terrain layer, or the ground layer where it belongs to no reference, which some cells use for their land) and pass through everything else. A miss leaves a hole (no triangles touching it). Interiors have no land and skip this.
- **Statics**: the real collision of every loaded reference with static collision (layers static, animated static, ground, trees, stair helpers and transparent, plus clutter on bodies that don't move: buildings, walls, doors, rocks, bridges, tree trunks, interior rooms, railings, plank floors, chests), read from its Havok shapes with Havok's own body transform. Triangle meshes come as they are (walking `hkpShapeContainer` keys, so MOPP and compressed meshes need no decoding of their own); boxes and convex hulls become their faces, capsules 8-sided prisms. Shapes that carry a transform of their own (convex transform/translate, transform: planks, railings, drawbridges, doors are often boxes in these) are read with Havok 2010's layout, which CommonLib lacks, and only when that transform is a real rotation; anything else, and spheres, is skipped and counted in the log. A triangle belongs to the chunk its center is in. Loose clutter, actors, debris, water and triggers stay out. When a door opens or closes, the chunks within 256 units of it are read and sent again 1.5 s later, once it has swung.
- **Roads**: the navmesh triangles flagged preferred (`BSNavmeshTriangle::kPreferred`, what Bethesda puts on roads for NPC pathing; deleted ones left out) of every loaded cell's navmeshes, flat (x, y only), that reach within `kRoadReach` (512 units) of the chunk. MSC uses them only to decide where ramps go. Landscape textures would say the same but are only per 2048-unit quadrant at runtime.

The 5 x 5 chunks around the player are sampled nearest first, then the 5 x 5 around a point 2 s of travel ahead of it (at most 2 chunks ahead, so it only matters while driving), about 2 ms of raycasts per frame plus well under 1 ms to read a chunk's statics. A chunk is done once at least 99% of its land samples hit (a few always miss at cave mouths) and no static in it is still waiting for its 3D; otherwise it is sampled again every 2 s (up to 5 tries) and resent when it improves. Skyrim forgets chunks more than 3 away from both centers and MSC drops them more than 6 away from the player, so a chunk MSC dropped is always resent.

MSC side (`msc/src/Link/CollisionChunk.cs`, `msc/src/Game/PlayerLink.cs`): one `MeshCollider` per chunk under `PerkeleRim.Island`. A chunk holds land and statics in one collider, so MSC finds the ground by casting again below each hit (Unity reports one hit per collider). A player with no island surface left under its feet but one above (it stepped into a rock, whose inside is not solid, and slipped below the land) is put back on the nearest surface above within a quarter second; vehicles already were. Chunks copy the layer, surface tag and physics material of MSC's asphalt (`Terrain` layer, tag `Concrete`, material `Track`): vehicle wheels only see some layers and take their grip from the surface. A new anchor clears them; the player is held at the anchor with its motor off until a chunk under it has arrived, then put down on it.

Before building a chunk's collider MSC adds ramps over its short steps (`msc/src/Link/Fillets.cs`): the top surface sampled on a 25 cm grid, and a level deck (12 of the 25 points around it within 15 cm) 3 cm to 0.8 m above the ground next to it lays a 1 in 5 slope down from itself as extra triangles. Only on the road: a deck point lays a slope only when it and its four neighbors are inside road triangles, and a point it raises must be within 0.75 m of one. A chunk without road triangles gets no ramps.

Log lines: `collision: chunk (x,y) gen N try T: terrain hits/1089 (passed through N), statics N triangles from N refs (N not loaded yet, N shapes skipped), roads N triangles from N navmeshes, ms + ms statics + ms navmesh` in `PerkeleRim.log`; `player: chunk (x,y) gen N: N vertices, N triangles (N ramp), N road triangles, ramps took ms, new|rebuilt`, `player: dropped N far chunks`, `player: placed on the island for gen N after S s` in MSC's log.

## Vehicles

`VehicleState` (MSC → Skyrim, latest-value slot): vehicle id (`kVehicleHayosiko`), flags (`kVehicleValid` while it is on the current anchor's island, `kVehicleDriven` while the player sits in it), anchor `generation`, position of the vehicle's origin, rotation as a quaternion in Skyrim space (local +Y forward, +Z up), velocity, front wheel steer angle (radians, positive turns right) and each wheel's spin angle about its axle (radians in [-π, π], positive rolls forward), which Skyrim applies to the van mesh's `Wheel*` and `Wheel*:Spin` nodes. One vehicle for now.

`VehicleParts` (MSC → Skyrim, latest-value slot, written right after `VehicleState`): vehicle id, anchor `generation`, `count` and up to `kVehiclePartCapacity` (48) `VehiclePart`s: rotation (quaternion) and pivot translation relative to the vehicle's body in Skyrim axes and units, and `kPartVisible` while MSC draws the part. Part `i` is entry `i` of the vehicle's fixed list, `kHayosikoParts` in the header: MSC hierarchy paths below the van's root (doors, steering wheel, key, gauge needles, pedals, levers, wipers, fuel hatch and cap, radio tuner, seatbelt, and the lit meshes: beams, brake, reverse, blinkers, gauge backlight and dashboard lamps). The C# mirror (`Wire.HayosikoParts`) and `tools/nif/hayosiko.json` list the same paths, and `msc/tests` checks all three agree. Changing the list bumps the version. A part's pose is relative to the body, not to its MSC parent, so nesting doesn't matter on the Skyrim side.

MSC side (`msc/src/Game/VehicleLink.cs`, one instance per vehicle): each vehicle remembers where it was left in Skyrim (position, rotation, worldspace or interior cell). At a new anchor in that same space it goes back there; in another space (a load door into Dragonsreach) it is held far below the island and not sent, so Skyrim hides it, until the player is back. Snapshots keep that space too. Only a vehicle that was never placed yet, or the van with the garage spot, is parked next to the player as before: when the player is put down on a new anchor on foot, the van is parked to its right and the Jonnez moped to its left, each at the first spot on its own side (usual, 4 m ahead, 4 m back, 3 m further out) where the ground under its center and corners is within 0.4 m, dropped above the highest point (a rock under one corner used to throw it, sometimes into the player); a vehicle the player sits in is moved to the new anchor with the player in it and set down on its wheels at the ground there. Both get their key (`PlayerKeyHayosiko`, as MSC's debug "Keys" command does) and a full tank. A vehicle with no island ground under it is made kinematic and keeps its velocity until the ground arrives. Only the van has a wire id, so only it is sent. Every frame it also reads each listed part's transform relative to the van's root and whether it is drawn (object active and renderer, if any, enabled): MSC switches lights and lamps by turning objects or renderers off.

Skyrim side (`skse/src/vehicle/VehicleView.cpp`): the van mesh converted from the player's own MSC install (`Meshes\PerkeleRim\Hayosiko.nif`, see [tools/README.md](../tools/README.md)), or a vanilla cart stand-in (`Furniture\Cart\CartFurnStatic01.nif`) when it wasn't converted, loaded through `BSModelDB` and hung under the player's parent node, posed every frame from a valid `VehicleState` of the current generation. While the player drives it (`skse/src/player/PlayerSync.cpp`), it is hung around Skyrim's camera instead of at MSC's pose: Skyrim builds the camera before the `PlayerCharacter::Update` hook from the previous frame's placement and smooths small moves, so the van jittered and fell behind at speed. The camera's spot in the van is learned while the van is below 0.5 m/s and kept for the session; the player's character controller isn't simulated while seated (like a rider). It has no reference and no Havok collision, so the collision sampler never sees it. The converted mesh has one node per listed part, named by its path; VehicleView sets each from `VehicleParts` (same vehicle and generation) and app-culls the ones MSC doesn't draw. Lit parts use Skyrim's glow shader, so they glow while shown.

Log lines: `vehicle: found/wheel models/N/40 parts/parked/got in/got out` and `surface: ...` (MSC's ground surfaces, once per game load) in MSC's log; `vehicle view: model ..., N of 4 wheel nodes, N of 40 part nodes, showing/hidden` and `player sync: ... seated=true van shift=D` (how far the van was moved off MSC's pose to stay around the camera) in `PerkeleRim.log`.

## Input

MSC runs hidden while Skyrim has focus, so it can't read the keyboard and mouse itself. Skyrim captures input and writes `InputState`. The MSC mod redirects every `UnityEngine.Input` call in the game's assemblies (cInput included) to a shim and answers from the latest `InputState`. `Input.mousePosition` answers with the screen center (MSC aims its look-at raycasts through the cursor, which isn't locked while its window has no focus). Details and measurements: [SPIKE_HIDDEN_MSC.md](SPIKE_HIDDEN_MSC.md).

- `keys`: 512-bit set of held Unity `KeyCode`s (mouse buttons are `Mouse0`..`Mouse6`). The shim derives Down/Up edges per MSC frame.
- `mouseX`, `mouseY`: the `Mouse X`/`Mouse Y` axes **accumulated** since Skyrim started. The two games run at different frame rates, so MSC applies the difference since its last frame; a per-frame delta would be lost or doubled.
- `mouseWheel`: the `Mouse ScrollWheel` axis, accumulated the same way (`kWheelAxisPerNotch`, 0.1 per notch, Unity's default). MSC uses the wheel for the radio dial, among others.
- `horizontal`, `vertical`: the Unity axes, -1..1.
- `flags & kInputOwnsPlayer`: MSC should apply this input at all. `flags & kInputPaused` (only with `kInputOwnsPlayer`): a Skyrim menu pauses the game (Escape, the map, inventories, not dialogue), so MSC sets `Time.timeScale` to 0.0001 (not 0: MSC's character motor divides by `Time.deltaTime`, and 0 turned the player's position into NaN) and pauses its sound (`AudioListener.pause`) until it clears, then restores its own scale (`msc/src/Link/PauseClock.cs`): nothing rolls, drains or ages behind the menu.
- `screenWidth`, `screenHeight`: Skyrim's back buffer in pixels, the size MSC renders its hand layer at.

Skyrim side (`protocol/cpp/input.h`, `skse/src/player/PlayerSync.cpp`): DirectInput scan codes and mouse buttons map to Unity `KeyCode`s; Escape, Tab, `~`, F5, F9 (quicksave and quickload; in MSC F9 switches to its cinematic camera), F10 and M (Skyrim's map) never reach MSC. Mouse counts become axis units (`kMouseAxisPerCount`, 0.06 per count, Y flipped). The wheel arrives as mouse buttons 8 (up) and 9 (down), one press per notch; Skyrim's own wheel zoom refuses while MSC owns the player (see above), and so do the keyboard keys that open Skyrim's menus (P magic, J journal, I inventory, T wait, Q favorites; MSC uses them all) except Escape, Tab and M (the map). While a menu has the input, keys and axes are sent empty so MSC stands still, and while it pauses the game `kInputPaused` freezes MSC's time. Every frame, keys and mouse buttons the devices no longer report as down are released, in case a release event got lost. MSC side (`msc/src/Link/InputFrame.cs`, `msc/src/Game/PlayerLink.cs`): the shim pulls the newest `InputState` before the first `Input` call of each MSC frame; the first state after a handover only seeds the mouse totals.

MSC's hand actions get keys next to WASD while handed over (`msc/src/Link/KeyRemap.cs`): an alias key held becomes the key MSC's action is bound to (read from cInput, so a player's own bindings are followed), MSC's own keys keep working, and standalone MSC keeps its bindings. V, middle click, Alt (piss, held), C (smoke, "cigs") and B (zoom) work everywhere, so Ctrl crouches on foot. G and T only on foot, since in a vehicle they are MSC's shift up and boost; driving, Shift and Ctrl shift gears up and down instead. ## Handing over the player

F10 in Skyrim toggles who owns the player. The first F10 of a save (when `PerkeleRim.esp` is loaded) first moves the player to the garage spawn marker; once its cell is attached and the player stands there, the handover below runs with `kAnchorVehicleSpot` and the van marker as `vehicleSpot`, so MSC parks the van inside the garage instead of next to the player. The SKSE cosave remembers this per save. Taking over:

1. Skyrim sends `WorldspaceChange` with the player's position and heading as `spawn` (a new `generation` each time), then publishes `InputState` with `kInputOwnsPlayer`; from then on Skyrim's own input handlers for MSC's keys refuse (see Rings, input pass-through).
2. MSC drains its ring before writing a pose, so the anchor is always applied first. The anchor maps to `Island.Base` on a collision island far from MSC's map, built from `CollisionChunk`s (see above). MSC holds the player's feet at the anchor until the ground there arrives, then puts it down.
3. Every frame MSC writes `PlayerState` (feet position in Skyrim world space, velocity, heading, camera pitch, stance from the `Crouch` FSM, and the anchor `generation`). `kPlayerValid` is set only while MSC owns the player and stands on the current anchor's island. `kPlayerBlocking` is set while MSC's player guards (right click with free hands), see [Combat](#combat). With `kPlayerCamera` it also carries MSC's rendering camera: `eye` (camera minus feet, Skyrim axes and units), `roll` (positive tilts the view right) and `fov` (vertical degrees), so leaning (Q/E), reaching for the door while seated, crouching and the zoom (B while handed over) all show. With `kPlayerNeeds` it carries MSC's needs in `kNeed*` order: thirst, hunger, stress, urine, fatigue, dirtiness (globals `Player*`, 0..100) and drunk level (`PlayerDrunk`, 0..8).
4. Skyrim's `PlayerCharacter::Update` hook places the player at every valid pose whose `generation` is the current one (a pose with a NaN or infinite value is skipped, so a broken MSC pose can't wreck the camera) (position, heading, pitch, zeroed controller velocity) and sets sneak while the stance is crouch or prone. Skyrim has already built its first-person camera by then (from the previous frame's placement, pivoting around the head), so the hook then overrides the camera node: placed feet plus `eye`, turned to the pose's heading, pitch and `roll` (`protocol/cpp/camera.h` keeps whatever axes Skyrim's node has on top), and sets `worldFOV` from `fov` (converted to Skyrim's horizontal-for-4:3 value; the old value comes back on release). A driven van is hung around the camera minus `eye`, and its seat is only learned while the view is level against the van (MSC moves the seated player when it leans), so leaning moves the view inside the van.
5. Skyrim draws its own HUD layer while MSC owns the player (`skse/src/hud`): a small dot at the screen center (Skyrim's crosshair is hidden then) and the latest `LookAtText` below it: a hand icon with `kLookAtUse`, the text on a dark box. MSC's needs as bars bottom left above the magicka bar, like MSC's own HUD (urine always yellow, any bar 80 % full turns red, urine orange; the drunk bar is full at level 4), and the latest `Subtitle` on a dark box near the bottom center.
   MSC's drunk level also drives a blur with double vision (the `PerkeleRimDrunkIMAD` imagespace modifier from PerkeleRim.esp, looped), its strength the drunk level / 4, so it grows and fades with MSC's own and is full where the drunk bar is.
6. If the game moves the player itself while MSC owns it (another worldspace or interior cell, or a jump of more than 2048 units: load doors, fast travel, scripts), Skyrim sends a new anchor and the island is rebuilt there.

F10 again, or the link going down, hands the player back to Skyrim.

## Coordinates

On the wire everything is in **Skyrim world space**. MSC converts on its side and adds the collision island offset.

- Skyrim: X east, Y north, Z up (right-handed), game units. Heading is the Z angle in radians, 0 = north, clockwise seen from above. Pitch positive looks down.
- Unity: X east, Y up, Z north (left-handed), meters. Yaw is `eulerAngles.y` in degrees, same zero and direction.
- Scale: 1 unit = 0.0142875 m, Havok's world scale in Skyrim (69.99 units per meter).
- Positions map axis by axis (Y and Z swap, which also flips the handedness), so angles keep their sign. Results are normalized to [0, 360) degrees or [0, 2π) radians.
- One function per direction on each side (`coords.h`, `Coords.cs`), both checked against the same vectors in `protocol/tests/coords_vectors.csv`.
