## Section layout

One section, `Local\PerkeleRim.Link`, 4,513,792 bytes. Whichever game starts first creates it; it disappears when both have closed.

| Offset | Size | Part | Written by |
|---|---|---|---|
| 0 | 128 | `LinkHeader`: magic, sizes, creator version, one `PeerInfo` per side | creator, then each side its own `PeerInfo` |
| 128 | 128 | `InputSlot` (latest `InputState`) | Skyrim |
| 256 | 128 | `PlayerSlot` (latest `PlayerState`) | MSC |
| 384 | 4 x 128 | `VehicleSlot` per vehicle (latest `VehicleState`, vehicle id v at 384 + (v - 1) x 128) | MSC |
| 896 | 4 x 8256 | `VehiclePartsSlot` per vehicle (latest `VehicleParts`, likewise) | MSC |
| 33920 | 5184 | `ItemSlot` (latest `ItemState`) | MSC |
| 39104 | 64 | `HandLayerSlot` (latest `HandLayer`) | MSC |
| 39168 | 1600 | `ActorSlot` (latest `ActorList`) | Skyrim |
| 40768 | 16448 | `ParticleSlot` (latest `ParticleState`) | MSC |
| 57216 | 64 + 4 MiB | ring Skyrim → MSC (collision chunks, worldspace changes) | Skyrim produces, MSC consumes |
| 4,251,584 | 64 + 256 KiB | ring MSC → Skyrim (look-at text, later events) | MSC produces, Skyrim consumes |

Layout rules:

- Everything is packed (`#pragma pack(1)` / `StructLayout(Sequential, Pack = 1)`), little-endian and fixed size. C# field names match the header.
- `LinkHeader` is frozen across versions. Any other layout change bumps `kProtocolVersion`.
- The C++ header `static_assert`s every size and offset. The C# tests parse those asserts and the `k*` constants out of the header and check the C# mirror against them, so the two can't drift silently.

## Handshake and liveness

Both sides run the same state machine (`Detached` → `Waiting` → `Up`, or `Disabled`), ticked 10+ times a second. Skyrim ticks it on its own thread at 20 Hz, so it also runs in menus. MSC ticks it from `Update`, so the heartbeat stops whenever MSC's main loop stalls.

1. Create or open the section. A fresh section gets its header filled in and the magic written last; a joining side waits while the magic is still 0.
2. Unknown magic or header size: the link is disabled (`not a PerkeleRim link`).
3. Each side publishes its `PeerInfo` (version, pid), even when the versions differ, so both sides can report a mismatch. If the creator's version, or the peer's, differs from ours, both log `protocol mismatch: ... speaks vN, this ... speaks vM` and stay disabled until restarted.
4. On attach, a side throws away whatever is left in its inbound ring (sent to an earlier instance of itself).
5. Each tick bumps our heartbeat. The link is **up** while the peer's heartbeat keeps moving. The first read only seeds the value, so a crashed peer never looks alive. It goes **down** after 2 s without a heartbeat change (e.g. MSC loading a scene) or at once when the peer detaches cleanly (pid set to 0).

Log lines on both sides: `created shared memory` / `joined shared memory`, `link up: <peer> pid N, protocol vN`, `link down: ...`, `link disabled: ...`. The Skyrim side logs to `PerkeleRim.log` (prefixed `link:`), the MSC side to the MSCLoader console and `output_log.txt` (prefixed `PerkeleRim:`).

## Latest-value slots

Continuous state (`InputState`, `PlayerState`, `VehicleState`, `VehicleParts`, `ItemState`, `HandLayer`, `ActorList`) goes through a seqlock slot, not a queue: the reader only ever wants the newest value, and a queue would add lag. The writer bumps `seq` to odd, writes, then bumps it back to even. The reader retries if `seq` changed or was odd. `seq == 0` means never written. Reads return nothing while the link is down.

## Rings

One single-producer, single-consumer byte ring per direction, for messages that must all arrive (collision chunks, events). `head` (producer) and `tail` (consumer) are monotonic byte counts on separate halves of the ring header. A record is an 8-byte `MessageHeader` (`type`, `size`) plus payload and may wrap around the end. `Send` refuses while the link is down, when the ring is full, or when the message can never fit.

## Models

MSC sends its own meshes and textures and Skyrim builds them in memory: nothing is converted offline or written to disk, so the mod ships none of MSC's assets. A model is a set of active `MeshRenderer`s below one MSC object (for items: see [Items](#items)), as one blob (`ModelHeader` with name and counts; per texture a `ModelTexture` header and RGBA8 pixels, top row first; per submesh a `ModelMesh` header with its path below the object, texture index, `ModelVertex` position/normal/UV and 16-bit triangle indices). Positions are in Skyrim axes and units relative to the object's position and rotation, with its scale applied, front faces counterclockwise seen from the front, UV (0, 0) top left. The blob is cut into `ModelChunk` messages so it fits the 256 KiB ring whatever its size; Skyrim's `Model::Assembler` (`protocol/cpp/model.h`) puts it back together and `Model::Parse` checks every bound. Encoded by `msc/src/Link/Model.cs`.

Materials (v12): after the textures the blob has `materialCount` `ModelMaterial`s and each `ModelMesh` names one (`material`, -1 = opaque, lit, no highlight). A material carries `kMaterialCutout` (alpha below `alphaCutoff` isn't drawn: MSC's Standard cutout mode, the beer case's grid), `kMaterialBlend` (alpha blended), `kMaterialUnlit` (MSC's Unlit/GUI shaders), `kMaterialOverlay` (no depth writes, for the death overlay), a highlight color and glossiness, and an emissive color. MSC bakes its color tint and a metal's darker diffuse into the texture, so the texture is the final diffuse; Skyrim has no reflections for these, so smooth and metal surfaces get only a soft highlight. MSC sends one texture per material, shared between materials that bake to the same one (copies of one material).

Nodes (v27): after the materials the blob has `nodeCount` `ModelNode`s (name up to `kModelNodeNameMax` = 64 bytes, `parent` index or -1 for the model's root, always before the node itself, and a rest pose relative to the parent: translation and rotation quaternion, Skyrim axes and units), and each `ModelMesh` names the node it hangs under (`node`, -1 = the root), its positions relative to that node. Skyrim builds one `NiNode` per model node, named by it, so a model can have parts that move on their own: the van (see [Vehicles](#vehicles)) has a node per wheel and per `kHayosikoParts` entry. Items and overlays have none.

Lights (v35): after the nodes the blob has `lightCount` (header field, at most `kModelLightMax` = 32) `ModelLight`s: one per MSC `Light` below the vehicle that Skyrim draws, with its role (`kLightLow`/`kLightHigh` beams, `kLightTail`, `kLightBrake`, `kLightReverse`, `kLightInterior`, the Gifu's `kLightWork` and `kLightBeacon`; the blinkers and the moped's dummy light are left out, `VanModel.LightRole` picks the role from the object's path and type), color and where it shines from and along in the vehicle's frame. `VehicleParts.lights` has bit i set while light i is on (enabled, object active), and `lowLevel` / `highLevel` are the beams' brightness (MSC intensity over the van's 3 and 4, so the moped's RPM-driven lamp dims and brightens). Skyrim picks reach and color itself.

MSC (`msc/src/Game/ModelSender.cs`) reads textures by drawing them into a RenderTexture and reading that back at the end of a frame into an `ARGB32` texture (MSC's textures have no CPU copy, and Unity 5.0's `ReadPixels` refuses `RGBA32`); larger than 1024 is halved. Skyrim (`skse/src/model/ModelView.cpp`) makes D3D11 vertex and index buffers and a mipmapped texture itself, wraps them in a `BSTriShape` cloned from a vanilla mesh and a `BSLightingShaderProperty` with Skyrim's flat default normal map, under one `NiNode` in the player's scene node, so the world lights it. The beer case with its bottles (25 submeshes, 1794 vertices, two 512 x 512 textures) builds in about 5 ms with no measurable frame cost.

A model's id (`ModelChunk.model`, never 0) stands for what it is made of: MSC keys it by the meshes and textures (by name, size and bounds, since every spawned copy of an item has its own mesh instance) and their placement, so identical items share one id and one model. MSC sends each model once per link session and everything again after the link comes back up; its ids start at a random base, so a restarted MSC never reuses an id a running Skyrim still has. Skyrim keeps every model it got by id (a resend replaces it) and builds a fresh node from it per item. Hand-built textures, the temporary materials and item nodes are never freed: the game's destructors expect objects it built itself, so item nodes are kept per model and reused. Spike command `textures <name>` reads any object's model and logs it without sending it.

## Items

`ItemState` (MSC → Skyrim, latest-value slot): MSC's frame, the anchor `generation`, `count` and up to `kItemCapacity` (128) `ItemPose`s, closest to the player first: MSC's item `id` (stable while the item exists, never 0), the `model` id of its look (0 = nothing to draw), `flags` (`kItemVisible` while MSC draws it, `kItemHeld` while it is in the player's hands) and its root's position and rotation (quaternion) in Skyrim space. An item missing from one frame to the next is gone. Only written with items while MSC has the player on the current island; otherwise `count` is 0.

MSC side (`msc/src/Game/ItemLink.cs`): every 0.5 s it looks for `Rigidbody` objects within 15 m of the player's feet (kept until 50 m, so a thrown bottle stays drawn all the way) that are MSC items: named `...(itemx)` or under `ITEMS`, or any non-kinematic loose rigidbody up to 30 kg that isn't part of the player or of something 100 kg or heavier (a thrown bottle; not the van's doors). Each item is split: its root's own renderers are one entry, and each direct child with renderers is an entry of its own, posed on its own. A beer case's bottles are its children, so a drunk bottle simply disappears, and all bottles share one model. Poses go out every frame; a destroyed piece drops out the same frame. When a new anchor moves the island under the player (the next handover, a load door), the items are moved by the same offset so each stays where it was in Skyrim's world, as long as that is within 50 m of the player; the rest stay behind. MSC itself does all the handling (picking up, carrying, dropping, throwing, drinking); mouse and keys already reach it. Spike command `items` logs every entry with its path and model id.

Skyrim side (`skse/src/item/ItemView.cpp`): one node per item id, made by `ModelView::Instance` once its model has arrived, hung under the player's parent scene node like the van (no reference, no collision), posed every frame and app-culled while not visible. Items that go away, change model, or all of them on F10 or an anchor change go back to a per-model pool for reuse.

`kItemForm` (v46): `model` is a Skyrim form id instead of one of MSC's models, for junk thrown from Skyrim's inventory ([Throwing junk](#throwing-junk)). MSC sends it for its body of a piece of junk, visible while it is active (its own renderers are off). ItemView draws a copy of the form's own model (`TESModel` path through `BSModelDB`, its collision taken off) with its origin at the item's position; a form whose model doesn't load is logged once and stays undrawn. These share the pool, apart from MSC's model ids.

## Smoke

MSC's smoke is drawn in Skyrim particle by particle (v34): the exhaust of the van, moped and Kekmet, the player's tire smoke and the player's cigarette smoke. They all use legacy Unity `ParticleEmitter`s in world space, textured with sprite sheets (`carsmoke` is 4 x 4 frames).

`ParticleState` (MSC → Skyrim, latest-value slot, rewritten whole every frame): `frame`, `generation` (the `WorldspaceChange` the positions are for), `count` and up to `kParticleCapacity` (512) `ParticlePose`s, closest systems first. A pose is the particle's look (`model`, a `ModelChunk` model id), its center in Skyrim world space, its width in units, its rotation on screen, `color` (r, g, b, a: the particle's color times its material's `_TintColor` doubled, as `Particles/Alpha Blended` draws it) and `sheet` (columns, rows and the frame it shows: Unity's UV animation steps through the frames `uvAnimationCycles` times over the particle's life, left to right from the top row).

A particle's look is a one-square model of its texture (`ModelData.Particle`: 1 unit wide, alpha blended, unlit), sent once per texture and sheet layout like any model. Before sending, MSC clears the texture's faint alpha haze (alpha up to 10 becomes 0, the rest is stretched back) and fades each frame's alpha out toward the edge of its inscribed circle, so a frame never ends in a straight edge. Dark smoke (a material whose doubled tint is under 0.5: MSC's diesel exhaust) gets a black texture and each particle's alpha times one minus its grey: Skyrim's lighting shader adds the scene's light to whatever it draws, which turned dark exhaust pale, but black times any light stays black, so dark smoke only dims what's behind it. Light smoke (cigarettes) keeps its white texture and glows with its color times Skyrim's light at the player (`HandView::Light`).

MSC side (`msc/src/Game/ParticleLink.cs`): every 2 s it collects the emitters below the drawn vehicles (leaving out the player's own, since a seated player is a child of the vehicle: its rain and piss stream aren't exhaust), `Skidmarks/SkidSmoke` and the player's `.../Smoking/BreathSmoke`; every frame it sends the live particles of the active ones within 80 m. Pure helpers (color, frame, haze, edge fade, darkening) are in `msc/src/Link/ParticleLook.cs` with tests.

Skyrim side (`skse/src/particle/ParticleView.cpp`): a pool of square instances per model, hung under the player's scene node like the items. Each frame every particle takes one: turned to Skyrim's camera and by its rotation, scaled to its width, its material's `materialAlpha` and UV scale and offset (the frame) and its glow color set. Squares not needed this frame are culled. Alpha-blended model shapes (smoke, glass) never write depth: with depth writes the squares hid each other and the fog behind them, showing as dark hard-edged squares.

Spike commands: `particles [word]` lists every particle system in MSC's scene with its shader, texture and state; `smoke` lists the mirrored systems and their first particles; `smoke on|off` stops or resumes sending; `smoke puff [n]` bursts every active mirrored system; `smoke sheet on|off` sends textures as one picture instead of frames.

## Hand layer

MSC's first-person view (the hands, a bottle being drunk, tools in hand, gestures) is not rebuilt in Skyrim: MSC draws it and Skyrim lays the picture over its own frame. MSC already draws all of it with its own `HandCamera` (layer `Player`, over the world camera), so that camera's output is the layer.

`HandLayer` (MSC → Skyrim, latest-value slot): MSC's copy counter (`frame`), `flags` (`kHandLayerValid` while MSC draws into the texture every frame), `texture` (a legacy DXGI shared handle, `IDXGIResource::GetSharedHandle`), `width`, `height`, `format` (`DXGI_FORMAT`) and `costMicros` (MSC's CPU time for the layer, last frame). The texture is transparent where nothing is drawn and lives on the GPU both games use; only the handle goes through shared memory. `InputState.screenWidth`/`screenHeight` (Skyrim's back buffer) tell MSC the size to render at.

MSC side (`msc/src/Game/HandLayerSender.cs`, `SharedTexture.cs`): a hidden camera below `HandCamera` copies its settings every frame and renders into a render texture of Skyrim's screen size, cleared to transparent black. Right after it rendered, the texture is copied into a shared D3D11 texture and the context flushed (COM calls through vtable slots, no native DLL). That needs Unity's renderer on the main thread, so MSC must run with `-force-gfx-direct` (`scripts/launch-msc.ps1` passes it); without it the layer stays off and MSC logs why. A few first-person objects below `FPSCamera` sit on layer `Default` (the piss stream, sauna water, digging bar, tow rope) and are moved to `Player` while the layer is on; changing their layer only around the hidden camera's render doesn't work, Unity culls with the layer an object had when the frame started. Only for the hidden render (`OnPreCull` to `OnPostRender`, restored after, so MSC's own view is unchanged): the layer is lit neutrally (flat ambient 0.5, fog off, MSC's lights masked off layer `Player`, one directional light of its own at 0.8 from above left), so it looks the same at any MSC hour; the strays' `Particles/Alpha Blended` materials are swapped for copies with a runtime-built shader that also writes alpha (Unity's legacy particle shaders write `ColorMask RGB`, which left the piss stream invisible in Skyrim); and the far clip is at least 20 m (`HandCamera` stops at 5 m). Spike commands: `hands` (cameras, layers, first-person renderers), `handlayer on|off|tint|save`, `handlayer light <ambient> <sun>` (the neutral lighting).

Skyrim side (`skse/src/hands/HandView.cpp`, `skse/src/hud/Hud.cpp`): opens the handle with `OpenSharedResource`, wraps the texture in a hand-built `NiSourceTexture` (`ModelView::Wrap`) and registers it with Scaleform's image loader as `img://PerkeleRimHands<n>` (a new name per handle). A clip at the lowest depth of the HUD movie (created through ActionScript; `GFxValue::CreateEmptyMovieClip` takes a negative depth as "next highest") loads it and scales it over the visible frame, flipped vertically since Unity renders into textures bottom row first. So the hands sit under every HUD element. The HUD movie stays up under Skyrim's menus, so `PlayerSync`'s `MenuOpenCloseEvent` sink covers MSC's overlay the moment any Skyrim menu opens (Esc, Tab, M, Favorites, dialogue, the console; not the HUD, fader, cursor and the like), paused game or not (the `Update` hook doesn't run while paused): `Hud::Cover` hides the hands, the dot, the look-at prompt, the throw's charge and the tools icon (the needs, subtitle, gear and fuel stay), and the held drink and MSC's items hide too, until the last such menu closes. Log line: `player sync: MSC's overlay hidden (<menu> opened)` / `shown again (<menu> closed)`. The clip is tinted with Skyrim's light at the player (`HandView::Light`, an AS2 `Color.setTransform` multiplier): outdoors the sky's ambient plus half its sunlight, indoors the cell's (or its lighting template's) ambient plus half its directional color, scaled so a clear noon is 1, hue kept, never below 0.12. Nothing is copied per frame on Skyrim's side; the layer hides when MSC's copy counter stops for 0.25 s.

MSC's options menu takes the same texture while Skyrim shows it ([MSC's menu in Skyrim](#mscs-menu-in-skyrim), `kHandLayerMenu`).

Cost at 1920x1080 (2026-10-10): about 0.3 ms of MSC CPU per frame, MSC at 8.4 ms per frame, Skyrim unchanged at 16.5 ms (vsync). Known gaps: the hands are lit by MSC's sun and clock, and MSC's particle shaders write no alpha, so the piss stream is in the texture's colors but transparent in Skyrim.

## MSC's menu in Skyrim

Skyrim runs fullscreen, so MSC's own options menu (graphics, controls and key bindings, sliders, Resume) is used from Skyrim: F1 while MSC has the player opens it, drawn over Skyrim's paused world with Skyrim's cursor; MSC's world keeps running, as under its own menu. No message types: Skyrim asks with `InputState.kInputMscMenu` while it wants the menu up, MSC answers with `PlayerState.kPlayerMscMenu` while it is, and the menu's picture comes through the hand layer's texture with `kHandLayerMenu`. Either side can close it: F1 or Escape in Skyrim drop the request, MSC's Resume drops the flag. The rules (`protocol/cpp/msc_menu.h`, tested): F1 opens only while MSC has the player, the link is up and no Skyrim menu is open; Skyrim gives up after 3 s if MSC never opened it (`My Summer Car's menu didn't open.`), and stops waiting 3 s after closing its side; handing the player back or the link dropping closes it.

Skyrim side (`skse/src/menu/MscMenuView.cpp`): a menu of its own, `PerkeleRim MSC Menu`, pauses the game, shows Skyrim's cursor and disables the pause menu. Its movie, `Data/Interface/PerkeleRim/MscMenu.swf`, is an empty 1280x720 stage that the plugin's build writes (`protocol/cpp/swf.h`, `skse/tools/swfgen.cpp`, tested); PerkeleRim never ships Flash content of the games. Every frame, also while paused, the menu reads the hand layer, dims Skyrim's world (black at 45%) and draws MSC's menu over the visible frame through ActionScript like the HUD's hands (`img://`, flipped). While it's up `PlayerSync` sends `Builder::BuildMenu`: every key and mouse button as held, the mouse totals (MSC's sliders drag with `Mouse X`) but no `Horizontal`/`Vertical`, Skyrim's cursor (`MenuCursor`, 0..1 of its screen) and `kInputPaused`. MSC doesn't freeze its time for it (`OptionsMenu.Freezes`, tested): its toggles wait 0.2 s of game time after each flip and its sliders move by `Mouse X` per second, and MSC never pauses for its own menu either. F1 never reaches MSC while it has the player; Escape and F1 close the menu, and Skyrim's own menu keys stay shut while it's up and until the Escape that closed it is let go (`MenuOpenHook`). Log lines: `msc menu: F1, opening My Summer Car's menu`, `My Summer Car's menu is up`, `closed from Skyrim (F1|Escape)`, `closed`.

MSC side (`msc/src/Game/MscMenuLink.cs`, rules in `msc/src/Link/OptionsMenu.cs`, tested): while asked, MSC presses its own Escape through the input shim (`Systems/Options :: Open Menu` opens on Escape or F1, MSC's own menu key; Resume closes on either, so neither reaches MSC while Skyrim shows it), again every second until `PlayerInMenu` is set, and `PlayerLink.CloseMenu` leaves the menu open; once Skyrim drops the request `CloseMenu` closes it through Resume, which also saves the options. `HandLayerSender` turns the hands off and renders a hidden copy of the menu's camera (`Systems/OptionsMenu/CAM`, layer `GUI`) into the shared texture on transparent black. The shim's `Input.mousePosition` is Skyrim's cursor in MSC's screen pixels (`InputFrame.CursorPixels`), so the buttons' `MousePickEvent` (through `Camera.main`, which the menu's `Setup` FSM makes `CAM` while it's up, on layer `GUI`) hits what Skyrim's cursor is on. `CAM` gets Skyrim's aspect meanwhile (and its own back after): MSC's window is 640 x 480, and at 4:3 its picks sat 0.75 as far from the center as Skyrim's 16:9 picture of the menu; Unity's own mouse messages (`SendMouseEvents.DoSendMouseEvents`, PlayMaker's `MOUSE` events) are redirected through the shim too. The quit buttons (`Btn_Quit`, `Btn_ConfirmQuit`) have their colliders off while Skyrim shows the menu, so they do nothing: leaving MSC's game would drop the link. Log lines: `msc menu: Skyrim asks for it, pressing Escape`, `up for Skyrim`, `N quit button colliders off`.

## Damage and death

Skyrim's health is the only one. While Skyrim has handed the player over, MSC never lets its player die: a Harmony prefix on PlayMaker's `Fsm.ProcessEvent` drops MSC's `DEATH` event (vehicle crashes send it), a prefix on PlayMaker's `ActivateGameObject.OnEnter` skips turning on `Systems/Death` (the need deaths in `Database/PlayerDatabase :: Simulation`, drowning, wasps, the train; it must never start, `Activate Dead Body` destroys the player's `CharacterController`, `CharacterMotor` and `FPSInputController` in its first frame), a need death's dead-end state in `Simulation` (`State 6`/`7`/`9`/`10`, `Burn`) is sent on to `Loop` so MSC's needs keep ticking (the need is at 0 by then; thirst and hunger are put back to 200 and cost nothing here, Skyrim drains health for them, see [Needs](#needs)), a watchdog switches `Systems/Death` off again if anything else turned it on, and each vehicle's `DriverHeadPivot` keeps its seat: the `ConfigurableJoint` it hangs by is held unbreakable while handed over, renewed every frame since MSC sets the van's to break at 300 every frame, and seats whose vehicle wakes up later are picked up within 2 s (a hard hit broke it, and its `Death` FSM threw the driver out through the windshield as a free body that fell through the world or shook the camera), and the pivots below it are put back if anything else moves them more than 1 m. Each such death goes to Skyrim as `PlayerDamage` and costs half of Skyrim's max health (`Damage::Crash`, `protocol/cpp/damage.h`). Skyrim's own fall damage doesn't run while MSC places the player, so Skyrim follows MSC's feet height and `kPlayerGrounded` (`PlayerState.flags`) and applies the vanilla formula (`((height - fJumpFallHeightMin) * fJumpFallHeightMult) ^ fJumpFallHeightExponent`) when the player lands. A hit that kills, or a death in Skyrim combat, makes Skyrim take the player back, send `PlayerDeath` (MSC plays one of its `Death` group clips on its listener), show MSC's blood (`player_blood_vision`, sent ahead as the overlay model `PlayerBlood`) in front of the camera, and kill the player the normal way, ragdoll and reload included. MSC's player stays alive. Known gap: only crashes MSC itself counts as fatal hurt Skyrim; hard but survivable hits do nothing yet.

Healing: what MSC's player consumes heals a share of Skyrim's max health, never past it (`Damage::Heal`), small for drinks since Finn drinks them by the dozen: beer 3%, a shot 3%, kilju 5%, a bottle of booze 6%, spirit 8%, a cigarette 2%, food 15%. Milk, juice and coffee heal nothing. MSC (`msc/src/Game/ConsumeWatch.cs`, rules in `msc/src/Link/Consumption.cs`) watches PlayMaker's state changes through a Harmony prefix on `Fsm.SwitchState` while handed over and sends one `Consumed` per finished one: a drink when the player's `Drink` FSM leaves its drinking animation for throwing the bottle or glass (`Drink anim` → `Throw bottle` beer, `Drink anim 1` → `Throw bottle 1` booze, `Drink anim 2` → `Throw glass` shot, `Drink anim 8` → `Throw bottle 2` spirit, `Kilju` → `Calc`); a cigarette when `PlayerFunctions` finds one in the pack and lights it (`Check tobacco` → `Activate`); food when an item's `Use` FSM goes from eating to `Destroy` (`Eat`, `Eat 2`, a single sausage's `Fresh` or `Grilled`), unless the item is a bottle (its `Use` FSM has a `Check drink` state; the `Drink` FSM counts those). Log lines: `consume: <object> :: <fsm> <from> -> <to>, kind K` in MSC's log, `death: MSC's <kind> heals H health of N (max M)` in `PerkeleRim.log`.

## Safe seat

Seated in the Hayosiko van, the Kekmet or the Gifu (`VehicleState.vehicle` of the driven vehicle, `Damage::SafeSeat`), or climbed into the van or the Gifu's cab without driving it (MSC lowers the camera and lets the player move between the seats before Enter: its feet in the van's cabin, `Hitbox::InCabin`, the hitbox box from 40 units above its bottom to 50 under its top and 15 in from its ends, so the ground beside it, its bumpers and its roof stay out; the Gifu's cab is the front 135 units of its box, 20 in from its sides (the mirrors), from 78 units above its bottom (over the front tires) to 185 (under the cab's roof, which the tank and beacons stand over); the Kekmet, an open frame, is safe only while driven), enemies can't hurt the player. The vehicles' hitbox (below) doesn't replace it: it isn't there while driving, and Skyrim's player stands at full height where MSC seats it, its head out of the roof. `skse/src/safe`: god mode is on while the seat lasts (and given back as it was, also when MSC lets go), the player's `Actor::HandleHealthDamage` drops hits from attackers (`Damage::Incoming`), and `NotifyAnimationGraph` drops the events that start staggers, recoils, knockdowns and ragdolls (`Damage::PullsOutOfSeat`), so nothing pulls the player out of PlayerSync's seat placement. The moped protects nothing. MSC's own damage still lands: a crash (`PlayerDamage`) is applied with god mode lifted for that call (`Safe::OwnDamage`).

Hits on the player in a safe seat land on the vehicle instead (`skse/src/safe/MetalHit.cpp`). A melee hit is dropped at the call into the hit's entry from the melee collision handler (address ids 37650/38603, offset 0x38B/0x45A, the same call the Elden Parry mod hooks; checked to be a call before it is hooked), before Skyrim builds the `HitData`, so there is no grunt, no screen blood or shake, no hit reaction and no damage. An arrow, spell bolt, flames, beam or cone (`ArrowProjectile`, `MissileProjectile`, `FlameProjectile`, `BeamProjectile`, `ConeProjectile`) whose `AddImpact` (vfunc 0xBD) names the player is killed before it lands: its `weaponDamage` is set to 0 (the arrow collision handler, id 44204, hands the hit to the actor only above 0) and the hook returns null. `AddImpact` returns the impact it added, though CommonLib declares it `void`; every caller in 1.7.104 takes null as "no impact", and a hook that returns nothing crashes the game there. A hostile spell effect from someone else that still reaches the player (`MagicTarget::AddTarget`, vfunc 1 of `PlayerCharacter`'s fifth vtable) is dropped, sparking once per cast (a spell's other effects within 100 ms don't spark again); the plugin's own spells on the player are cast by the player and pass. Each plays the attack's own impact on metal (the attacker's weapon's impact data set, for a spell its costliest effect's, looked up for `MaterialMetalSolid`, then heavy and light metal; without one, Skyrim.esm's `Unarmed` weapon's): the impact's model at the point of the vehicle's box nearest where the hit came from (the attacker's `WEAPON` node, or 0.6 of its height for a creature; the arrow's impact point), its +Y along the box face's normal (`Hitbox::Surface`, tested), and its two sounds there. Each counts in `Hitbox::Hits`. Log: `metal hit: <attacker>'s <weapon> (<melee|projectile|spell effect>) hit vehicle N instead of the player at ...` (the first 16, naming the hook that caught it). Seated, PlayerSync also lowers Skyrim's player until the top of its head is 10 units under the box's top, the Gifu's under its cab's roof (`Hitbox::SeatDrop`, `Hitbox::Roof`, at most 120 units, none with the vehicle on its side; the van's driver seat about 63), so arrows meet the van's hitbox before the head; the camera stays at MSC's eye. `SeatDrop=0` in `PerkeleRim.ini` turns that off. The periodic `player sync:` line shows it as `drop=`. Climbed in, the player isn't lowered: its capsule is simulated then and stands on the van's floor.

## Vehicle hitbox

Skyrim-only, no protocol of its own. Every vehicle VehicleView draws gets a solid body in Skyrim's world (`skse/src/vehicle/Hitbox.cpp`, rules in `protocol/cpp/vehicle_hitbox.h`, tested): the box around MSC's model of it (`ModelChunk`, every mesh at its node's rest pose) filled with up to 12 capsules along its longest side, neighbours at most sqrt(2) radii apart so nothing slips between them (the van: 4 capsules). Each capsule is a keyframed Havok body built with Skyrim's own capsule shape (metal material), moved to the `VehicleState` pose every frame by `hkpKeyFrameUtility::applyHardKeyFrame` (a teleport after a jump of 300 units), in the player's cell's Havok world. Layer `L_ANIMSTATIC` (2), the layer of doors and moving platforms: it collides with projectiles, spells, cone projectiles (flames), line of sight (NPCs don't see Kumpo behind the van), character controllers, ragdolls and clutter. The collision sampler's rays pass through it (only terrain counts as land). `L_TRANSPARENT_SMALL_ANIM` (28) was tried first: Skyrim.esm's matrix has it colliding with projectiles and a projectile ray met it, yet arrows flew through it in game. `HitboxLayer=<n>` in `PerkeleRim.ini` puts the capsules on another layer for a test. The bodies carry the player's collision group, so the player's own capsule, which MSC places, goes through them. They leave the world while the vehicle isn't drawn, the player has no Havok world or collision group yet, and from `Damage::kRunOverSpeedMin` (2 m/s) until it slows under 1.5 m/s: a moving body would push people out of the way before MSC's run-over box reaches their capsules. With `HitboxTest=1`, every projectile whose impact names one of the capsules' collision objects counts as a hit on the vehicle. Log lines: `hitbox: the <vehicle> model ... N capsules of radius R`, `hitbox: the <vehicle> is solid in Skyrim's world ...`, `hitbox: the <vehicle> is out of Skyrim's world (<why>)`, `hitbox: <shooter>'s <projectile> hit the <vehicle> at ...` (the first 16, with `HitboxTest=1`). `scripts/hitbox-test.ps1` runs it unattended (`skse/src/vehicle/HitboxTest.cpp`, armed by `HitboxTest=1` in `PerkeleRim.ini`): two bandit archers with their AI off, 4 m behind the van seen from Kumpo and 8.5 m beside him, and a melee bandit 8.5 m behind the van. The test fires 12 arrows at Kumpo itself, 8 through the van and 4 from the side as a control, each starting at its archer: Skyrim first checks the line from an arrow's shooter to its start, so an arrow started away from its shooter hits whatever lies between them. Before each shot through the van it casts a projectile ray along the same line (`hitbox test: a projectile's ray ... meets the van's hitbox`). After a minute of `hitbox test:` lines it logs `hitbox test: done: 8 through-the-van arrows, N stopped by the van, M on Kumpo; 4 control arrows, ...; the melee bandit came within D units of Kumpo and stood inside the van's box in K samples ...`.

## Combat

`ActorList` (Skyrim → MSC, latest-value slot, written every frame while MSC has the player): Skyrim's frame, the anchor `generation`, `count` and up to `kActorCapacity` (32) `ActorPose`s, closest first: the actor reference's form `id`, its feet `position`, `heading` and `velocity` in Skyrim space, the capsule it stands for (`radius`, `height`, units) and its `mass` (kg, a guess from its bounds times its scale at a person's density, `Damage::Mass`; every dragon at least 2000). Only living actors that stand are listed: not dead, disabled, knocked down, ragdolled or riding; an actor missing from one list to the next has gone. Skyrim (`skse/src/combat/Combat.cpp`) takes the high-process actors within 2800 units (40 m) and sizes each capsule from its bounds times its scale (half the narrower side, the full height; a person when the bounds look wrong), logged once per actor. On release it writes an empty list.

MSC side (`msc/src/Game/ActorLink.cs`, math in `msc/src/Link/Actors.cs`): one kinematic `CapsuleCollider` per listed actor of the current generation, carried on by its velocity for up to 0.25 s between lists, on an unused layer that collides only with the player's layer; actors of 2000 kg or more (mammoths, every dragon) on a second one that collides with everything but the capsules; while the player drives, the others are switched off. The walking player bumps into people; vehicles, their wheels, items and MSC's raycasts with layer masks pass through (vehicles run people over instead, see below). All capsules go when MSC stops playing.

MSC's punch is its own: the Hit key (H) throws MSC's fist animation. Left click does too while the hands are free (`msc/src/Link/PunchButton.cs`): decided when it goes down, with no MSC prompt for what the crosshair is on (globals `GUIinteraction`, `GUIuse`), nothing in the hands (`PlayerHandLeft`/`Right`) and not in a vehicle, the click reaches MSC as its Hit key until let go; otherwise it stays MSC's click. MSC's hand icon flickers on and off while the crosshair is on an item, so a prompt seen in the last 0.5 s still keeps the click. MSC's own bindings are untouched. 0.15 s after the key (the fist is out), MSC sweeps a 0.15 m fist 2 m out of its camera (more than MSC's arm, since Skyrim's melee steps the attacker in and MSC's doesn't) against the capsules (`Actors.Punch`) and sends a `PunchEvent` for the first one it touches. No punches while seated in a vehicle. Skyrim checks the actor still stands within 400 units, then casts two of PerkeleRim.esp's spells from the player at it with the player as the one to blame: `PerkeleRimPunch` (damage health, magnitude set per cast to `Damage::Punch`) and `PerkeleRimPunchStagger` (stagger 0.5). Being the player's hostile spells, the target fights back and a hit on someone peaceful counts as assault, as Skyrim treats any attack. The damage scales like Skyrim's own fights: the player's unarmed damage as Skyrim works it out (`Actor::CalcUnarmedDamage`, the race's plus Fortify Unarmed; then the perk entry point Mod Attack Damage with Skyrim.esm's `Unarmed` weapon (0x1F4) and the target, so Fists of Steel and modded perks count; then the difficulty's multiplier on damage the player deals, `fDiffMultHPByPC*`), times `Damage::kPunchScale` (2), since vanilla unarmed is weak (4 for most races, 10 Argonians, 22 Khajiit). A sober level 1 Nord hits for 8 at Adept, about an iron sword's hit: a wolf in three punches, a soldier in six or seven. Target armor doesn't reduce it. Drinking pays off in a fight, since MSC's drunk camera makes aiming harder. MSC's drunk level (`PlayerState.needs[kNeedDrunk]`, 0..8 by the player's weight) climbs slowly: five beers are about 0.4, two dozen leave Finn staggering around 2.5, a few vodkas more black him out. Everything drunk scales with `Damage::DrunkShare`, the level over 3 (`Damage::kDrunkLevels`): the punch up to twice the sober one at drunk 3 (`Damage::DrunkPunch`). The first punch logs the parts (`combat: the player's unarmed damage: ...`).

Small creatures (mudcrabs, skeevers, small spiders) keep a capsule their own size (Skyrim lists bounds down to 8 units high as they are), but the punch and the push treat every capsule's axis as reaching at least 1.1 m above its feet (`Actors.ReachTop`), so a standing player reaches them looking a little down; a punch straight ahead passes over them. Thrown items don't get that.

Being drunk also toughens the player, while MSC has it (`Combat::Drunk`, `Damage::Drunk`): by `Damage::DrunkShare`, up to +200 armor rating at drunk 3 (Skyrim's `DamageResist`, so it adds to worn armor under Skyrim's cap; about a quarter less physical damage), +100 max stamina and +100% stamina regen (`StaminaRateMult`); five beers give about a seventh of that. These are PerkeleRim.esp's `PerkeleRimDrunkArmor` (0x914), `PerkeleRimDrunkStamina` (0x915), `PerkeleRimDrunkStaminaRate` (0x916), fortify effects with Recover, 10 s long, cast by Skyrim on the player with the magnitude set per cast (the running ones dispelled first, since a recast adds a copy instead of replacing them), again whenever the level moves by 0.1 and every 5 s before they run out. They show in Skyrim's Active Effects while MSC has the player as "Drunk: Thick Skin" (armor), "Drunk: Liquid Courage" (stamina), "Drunk: Second Wind" (stamina regen), each with its amount. Handback dispels them, and a save taken meanwhile loses them within 10 s of loading. Log, per tenth of the way to drunk 3: `combat: drunk L: casting armor +A, stamina +S, stamina regen +R% (the player has armor ..., max stamina ..., stamina regen ...%)`, the player's values from before that cast, so they show the last one took; `combat: sober again, ...`.

A swing (left click or H) also hits the destructible objects within 200 units in front of the player (`Combat::OnSwing`, Papyrus `DamageObject`, so their own scripts run): a spider web takes enough to cut it (one without a script is disabled), anything else 50. Destructibles lying flat on the floor (bounds under 16 units tall, other than webs: oil puddles) are left alone, by swings and throws alike, since a hit sets a puddle alight under the player's feet. MSC's punch only reports actors, so this is decided on Skyrim's side. Finn fights with his fists (`Combat::Disarm`): while MSC has the player, a weapon (staffs too), spell or scroll in either hand is unequipped every frame it shows up (`ActorEquipManager::UnequipObject`, spells `Actor::DeselectSpell`), with a short notification (at most every 3 s). Shields, torches, shouts and powers stay. Nothing is equipped back at handback. Armor works as in vanilla.

Blocking is Skyrim's own (`msc/src/Link/BlockButton.cs`, Skyrim side `Combat::Guard`): holding the right mouse button with the hands free (decided when it goes down, the same rule and 0.5 s prompt grace as the punch's left click) reaches MSC as its Watch key (U) until let go, so `PlayerFunctions` raises the left arm to the watch (`Watch ON 2` while held) and lowers it on release; left click and the Hit key are dropped meanwhile, so no punches while guarding. With an item in hand the right click stays MSC's throw; U is still MSC's watch. MSC sets `kPlayerBlocking` in `PlayerState.flags` while guarding, not a ring message, so a lost message can't leave Skyrim blocking. Skyrim keeps the player's hands drawn while MSC has it (Skyrim only blocks with them out: fists, or whatever is equipped; not while a menu such as dialogue has the input), with its first-person model culled so they don't show over MSC's hands, and, while the flag is set, on foot and with no menu up, sets `wantBlocking`, sends the graph `blockStart` (`blockStop` when it clears) and sets the graph variable `IsBlocking` on both graphs (third and first person), putting it back whenever it no longer matches. The graph refuses `blockStart` while MSC has the player (it never sees the hands drawn, `iState` stays 0), so there is no block animation, but Skyrim's hit code only reads `IsBlocking`: hits count as blocked (`TESHitEvent` `kHitBlocked`) and the Block skill, its perks, stagger and power attacks apply as in vanilla. Handback, death and the link going down end the block, sheathe hands Skyrim drew and show the first-person model again.

Thrown items (rules in `msc/src/Link/Throwing.cs`): an item that leaves the player's hand within 0.5 s of the right mouse button (MSC's throw; a drop doesn't count) is followed for up to 4 s, until it's picked up again or hits. Bottles (names with "bottle", booze, spirit) fly twice as fast as MSC throws them, the first time their throw speed shows within 0.3 s: a ranged attack that reaches dragons. Each frame, while it's still at 2 m/s or more, its path since the last frame is swept with a 0.1 m radius against the capsules (`Throwing.Sweep`); on the first one it passes through MSC sends an `ImpactEvent` (`kImpactThrown`, its speed) and turns the item back at 0.3 of its speed, since capsules don't collide with items. Thrown items switch to continuous collision, so a fast bottle doesn't pass through the island's thin ground. Skyrim hits the actor with the punch spells, the damage by speed (`Damage::Thrown`): nothing at 2 m/s, rising to twice the player's sober punch (`Damage::Punch` of its unarmed damage, `Damage::kThrownShare`) at 15 m/s and more, since a throw is hard to aim; then by weight (v46, `ImpactEvent.mass`, `Damage::ThrownMass`): MSC's empty beer bottle (0.5 kg) as is, anything else by the square root of its mass against the bottle's, 0.5 to 3 times. MSC sends its rigidbody's mass, for junk the item's ([Throwing junk](#throwing-junk)); 0 counts as the bottle. Then by Kumpo's level (`Damage::ThrownLevel`, Skyrim's player level): 0.1 of the level 1 hit more per level. Then by MSC's drunk level (`Damage::DrunkThrow`, the `kNeedDrunk` Skyrim already has from `PlayerState`, no protocol change): x1 sober, x1.5 at 0.1 (a beer), x2 at 0.4 (five beers), x3 at 1, x4.5 at 2 and x6.5 from 3 on, linear in between, so a Nord's full-charge bottle hits 16 sober and 104 blind drunk at level 1, 70 and 458 at level 35. Then by the target's armor as Skyrim takes it off an arrow (`Damage::ArmorTaken`): what it wears (`Actor::CalcArmorRating`) or its `DamageResist`, the larger (a guard reads the same for both, so adding them counted it twice), 0.12% less per point, at most 80% less; the hit is a spell in Skyrim, which armor wouldn't touch otherwise. Skyrim's difficulty is in the punch it starts from (`fDiffMultHPByPC*`). The log line shows each factor and the target's health. A throw that hits an actor also trains Archery (`Damage::ThrownSkillUse`, `PlayerCharacter::AddSkillExperience`): skill use worth its sober, level 1, unarmored hit (16 for a full-charge bottle, about an iron bow's shot), Skyrim's own skill multipliers on top, so Kumpo levels while MSC has him; a second log line shows Archery's experience before and after. Destructibles (`Damage::ThrownObject`) and punches don't change. Sneak attack (`Damage::SneakAttack`, no protocol change): the first `ThrownPath` of a flight records whether the player was sneaking (`Combat::OnThrown`); at the `ImpactEvent`, if that throw left the hand from sneak (the player's stance now when no flight was seen in the last 10 s) and the target's `Actor::RequestDetectionLevel` of the player is 0 or below, the damage is doubled on top of the speed rule and Skyrim's "Sneak attack for 2.0x damage" message shows. Punches are spell casts in Skyrim, which have no sneak attack, and stay as they are. The log line shows the stance, the detection level and the multiplier.

Thrown items also hit Skyrim's destructibles (v36): hanging oil pots, spider webs, barricades. Those are not actors and mostly not on the island (webs are on Skyrim's debris layer), so MSC can't see them; instead, every frame of a flight at 2 m/s or more MSC sends its way as a `ThrownPath` in Skyrim world units. On a new flight Skyrim gathers the destructibles within 8000 units of the player (`Combat::OnThrown`, the same selection as a swing); a segment that passes within a destructible's 3D bounding sphere plus 7 units (30 units around its origin with no 3D) damages it once per flight through Papyrus `DamageObject` (`Damage::ThrownObject`): a web is cut at any speed, anything else takes the thrown damage off 50 (at least 1), so a fast bottle drops an oil pot. The item flies on; it isn't bounced. Log: `combat: a thrown item hit ...` in `PerkeleRim.log`.

Piss is poison: while MSC's stream object (`PLAYER/.../FPSCamera/Piss/Fluid`) is active, MSC reads up to 64 of its particles per frame and a drop within 0.05 m of a capsule hits that actor; with no particle system to read, the stream is a 1.2 s arc from `Fluid` along the camera at 3.5 m/s. Each actor gets an `ImpactEvent` (`kImpactPiss`) every 0.5 s at most while the stream stays on it. Skyrim casts PerkeleRim.esp's `PerkeleRimPiss` (0x90E, damage health per second, poison resistance applies, 5 s) with the magnitude set per cast to `Damage::PissPerSecond`: 2% of the target's max health per second, a dragon a quarter of that. Recasts refresh it, so the poison runs on 5 s after the stream leaves. Like the punch, it's the player's hostile spell, so it counts as assault. Running people over (rules in `msc/src/Link/RunOver.cs`): capsules under 2000 kg (people, wolves, bears, elk, cows) don't collide with vehicles, and while the player drives they are switched off altogether, so the van carries on through anyone and `CrashMeter` never sees it (the driver loses no health). Instead, while the player drives at 2 m/s or more, the vehicle's box (its own non-trigger colliders' bounds in its space, measured once per vehicle and logged) is checked against every capsule each frame (`RunOver.Touches`); a touched actor gets an `ImpactEvent` (`kImpactVehicle`, the vehicle's speed and way), once per 2 s at most per actor, since the list lags behind the knockdown. Huge capsules (2000 kg or more, every dragon: a mammoth) are solid instead: the vehicle stops on them as on a wall (a crash `CrashMeter` counts for the driver), and the hit goes out at the vehicle's speed from the frame before. Skyrim knocks the actor over first (`AIProcess::KnockExplosion` from 100 units behind it along the vehicle's way, magnitude `Damage::KnockOver` = 0.5 per m/s, 1 to 15), then casts `PerkeleRimPunch` with `Damage::RunOver`: nothing below 2 m/s (about 7 km/h), rising linearly to the target's whole max health at 50 km/h, twice its max health from there on (lethal), a dragon a quarter of that. No stagger spell, the knockdown does that. By weight (`Damage::BulkOf`): a light or heavy actor's ragdoll is then thrown (once it is a ragdoll, up to 30 frames, for 3 frames every rigid body's velocity is set to 1.2 times the vehicle's speed along its way plus 0.35 of it upward; the vehicle has no collision in Skyrim, so without it the body just drops through the van); a huge one (2000 kg or more, every dragon) isn't knocked over at all, it only takes the damage. Each hit MSC sends makes Finn swear (`PlayerVoice.Swear`, at most every 3 s).

The horn (v31, `msc/src/Game/VehicleHorn.cs`): MSC has no horn key, so H while driving plays the first MSC sound with "horn" in its name (else "beep"; candidates logged once) looped on the vehicle while held, and sends a `HornEvent` on the press and every second after; while driving, H (and MSC's Hit key) never reach MSC, so Finn doesn't punch in the seat. Someone already diving isn't sent again. A Skyrim fear spell was tried first: it moved nobody, and the people it was cast on later turned hostile and died.

Pushing (`ActorLink.Shove`, rule in `Actors.Touching`): MSC's push key (J, or G on foot) toggles MSC's own push stance, both hands up (`PLAYER/.../FPSCamera :: PlayerFunctions` in state `On`, until J again, the hand gets busy, a seat or a drink), and on its press also rights a rolled vehicle next to the player (`VehicleLink.RightIfRolled`). Heavier ones stay put. Log: `actors: shoved <id>` in MSC's log, `combat: the player pushed <name> aside (stagger from F)` in `PerkeleRim.log`.

All four kinds are checked against the actor still standing within the listed range (plus 400 units).

Shouts are Skyrim's own (`Combat::Shouts`, rule in `protocol/cpp/shout.h`): Z reaches Skyrim's shout handler as usual, so the equipped shout fires with Skyrim's words, cooldown and Dragon Souls, aimed along MSC's camera (PlayerSync turns the player to it every frame). Back to 0 at release and at data load. ## The pocket

Skyrim's inventory is the pocket for MSC's beer, juice, empty bottles, food and cigarettes: PerkeleRim.esp items (`tools/esp-gen`, ids 0x906 + kind for MSC Beer, Empty Bottle, Sausages, Pizza, Potato Chips, Macaron Box, Cigarette; 0x940 Juice, kind 8 `kPocketJuice`, v45), so they come along through load doors, weigh something, sell and live in Skyrim's saves. MSC Beer, Juice and the four foods are food items (with their vanilla look-alike's effects), eaten and drunk in Skyrim like any other food ([Food and drink](#food-and-drink)); the Empty Bottle and Cigarette are misc items. Kind 7 (`kPocketGold`) is Skyrim's own gold (`Gold001`), MSC's money. Kind 9 (`kPocketJunk`, v46) counts the junk Kumpo could throw ([Throwing junk](#throwing-junk)), less what is out in MSC's hand. Skyrim's counts are the truth; MSC (`msc/src/Game/PocketLink.cs`, rules in `msc/src/Link/Pocket.cs`) adds the changes it sent that Skyrim hasn't applied yet (`seq` above `appliedSeq`), so a second key press before Skyrim answers already sees the first.

While MSC has the player, Skyrim's Y is PerkeleRim's and never reaches MSC, and the number keys 1 to 8 send MSC whatever their favorites hotkey stands for ([The hotbar](#the-hotbar)): MSC's own 1 and 2 (hands, tools) for the Empty Hands and Tools powers, the pocket's keys below for Throw Empty Bottle, MSC Beer and MSC's food, nothing for an unbound number. The pocket keys below are those MSC keys (Alpha3 to Alpha8), whichever number sends them. In a vehicle only beer and food work (`Pocket.WorksInVehicle`), so the player can drink and eat while driving; nothing goes in or out of the hand there:
- Y puts what MSC's hand carries in the pocket, or, with empty hands, what the crosshair is on (MSC's own pick-up check: 1 m, item layers 19/15/9): one bottle of a beer case (the case is thrown away with its last bottle), an empty bottle (`empty bottle(Clone)`, what MSC throws after a beer), sausages, pizza, potato chips, a macaron box (not spoiled ones) or a juice (`juice(itemx)`; it has no pocket key, it's drunk from Skyrim's inventory). Food goes the way of MSC's garbage (its `Use` FSM's `GARBAGE`; an item without that event is destroyed), so MSC's save never brings it back.
- Pocket keys 3 to 8 (the hotbar's defaults put them on the same numbers), in fixed order: 3 empty bottle (to throw; with none left, junk), 4 beer, 5 sausages, 6 pizza, 7 potato chips, 8 macaron box. Beer and food are used at once: a beer is MSC's own beer drinking (`DRINKBEER`, as a beer case sends it: the animation, the needs, then the empty bottle; the one MSC throws, a new copy of `BottleBeerFly` that turns up within 10 s, is destroyed and goes into the pocket as an Empty Bottle instead, ready to take out with 3 and throw. A beer drunk from a held case keeps MSC's toss), not while the left hand is busy or a helmet is on; food is a new item from the store's spawner, hidden, put in its `Use` FSM's `Eat` state as soon as it has loaded (the sounds, the needs, then gone). Smoking doesn't stop either, as in MSC.
- 3 takes an empty bottle out into the hand (a copy of MSC's `BottleBeerFly`), which MSC's hand takes the way a click would (`1Hand_Assemble/Hand :: PickUp`: `RaycastHitObject`, then `FINISHED`). 3 again puts it back; with something else in hand that goes in the pocket, that goes in first (a case with more than one bottle is put down instead), anything else is dropped first.
- A slot with none left does nothing.

Left click punches only when nothing MSC would pick up is under the crosshair (the same check), so items without a prompt, like empty bottles, are picked up again.

Cigarettes aren't held: MSC smokes them with I from its global `PlayerCigarettes`, which stays equal to Skyrim's Cigarette count while the link is up. When the link comes up MSC's count wins (Skyrim has none of MSC's cigarettes the first time; gold below is the other way round on purpose: Skyrim's save already holds the player's gold, while cigarettes only ever come from MSC); after that a change on either side (smoking, a pack bought or picked up in MSC; dropping, selling or picking up in Skyrim, loading a Skyrim save) is copied to the other. MSC's snapshot in a Skyrim save leaves `PlayerCigarettes` out for that reason.

Gold is MSC's money (`PlayerMoney`), one gold per mark, the same way (`CountMirror`), except that the first time the link comes up in an MSC run Skyrim's gold wins: the Skyrim save is the truth, so loading an older save brings its money back (a new Skyrim character with no gold empties MSC's wallet). After a link flap (a long load) the count both agreed on still holds: a change on either side is copied, Skyrim's when both changed. MSC mirrors money only from 3 s after its player shows up, so its own save's money isn't taken for money spent or earned. MSC's pennies stay MSC's (Skyrim gets whole marks, `Pocket.Gold`; a change from Skyrim keeps them, `Pocket.Money`). Money spent or earned in MSC (a shop, a fine, a job) changes the gold; gold picked up, looted, paid or sold for in Skyrim changes MSC's money. MSC's snapshot in a Skyrim save leaves `PlayerMoney` out too.

Until v43 the pocket was endless (MSC topped every kind back up to a stock) and mead and ale picked up in Skyrim became MSC Beer. Both are gone: beer, food and bottles come from MSC (Y, the garage shelves) and from Skyrim's own food and drink. The HUD doesn't list the pocket.

To reuse (the gas stations do, [Fuel](#fuel); so does [throwing junk](#throwing-junk)): an Empty Bottle goes into MSC's hand through key 3's path (`PocketLink.Press(Alpha3)`, the Throw Empty Bottle power sends the same), and Skyrim's gold is MSC's money, so anything MSC charges is paid in gold with no extra code; Skyrim-side code that wants to charge gold just removes `Gold001` from the player and MSC follows.

## Throwing junk

Key 3 (the Throw Junk power, 0x91C) takes out a random piece of what Kumpo carries, MSC's empty beer bottles and junk from Skyrim's inventory alike (v46, rules in `protocol/cpp/junk.h`, tested):
- what is junk: misc items with Skyrim's `VendorItemClutter` keyword (tankards, plates, baskets; not pelts, gems, ingots, ore, lockpicks, keys or gold), and fruit and vegetables (`Junk::kProduce`: apples, tomato, gourd, cabbage, potato, carrot, leek, Dragonborn's ash yam). Never a quest item, one of PerkeleRim.esp's pocket items (its Cigarette is misc), or anything heavier than 10;
- which one: any piece, each as likely as the next, so a stack of ten comes up ten times as often as a single one. MSC rolls between its empty bottles and junk by their counts (`Pocket.ThrowKind`); for junk, Skyrim rolls among the pieces it carries (`Junk::Pick`, the random source passed in so the tests choose the roll).

How it goes: MSC sends a `PocketChange` of `kPocketJunk`, delta -1 (`PocketLink.StartTake`). Skyrim (`skse/src/junk/ThrowJunk.cpp`) picks the next piece and answers with a `JunkOut`: the `seq` of that change, the item's `form`, its `mass` (its weight as kilograms, at least 0.1, `Junk::Mass`) and its bounds (`OBND`, the model's own space). The item stays in Skyrim's inventory meanwhile, set aside (not picked or counted again). MSC (`msc/src/Game/JunkLink.cs`, rules in `msc/src/Link/JunkBody.cs`) makes its body: a copy of the empty beer bottle (`BottleBeerFly`, so it is picked up, carried, charged and thrown exactly like one, bottle speed included), named `junk(Clone)`, its renderers off and its colliders replaced by one box the size of the bounds (4 cm to 60 cm a side), and puts it in the hand as key 3 does a bottle. `ItemState` sends it with `kItemForm`, so Skyrim draws the item's own model on it, in the hand and in flight. Its hits count the item's mass (`ImpactEvent.mass`). No answer within 2 s (MSC then sends a `JunkBack` for the take, so nothing stays set aside), or `form` 0 (none after all), and nothing comes out; Skyrim sets nothing aside when it can't send the `JunkOut`.

## Saves

Every Skyrim save (manual, quick, auto) also keeps MSC's state. This isn't MSC's own save: broadcasting MSC's `SAVEGAME` mid-game makes its FSMs act as if quitting (Satsuma kinematic, items reset, driver unseated) and stalls MSC for 4 to 16 s, and its reload takes about 17 s through the main menu. Instead MSC captures what it can put back in place, from memory, in a few ms. MSC's real save still happens when MSC quits.

On `kSaveGame` Skyrim picks a new random key, sends `MscSave` with `Saves/PerkeleRim/<save name>`, and keeps the key, the save name and whether MSC had the player in its cosave (record `MSCS`). MSC (`msc/src/Game/SaveSync.cs`) writes `PerkeleRim_snapshot.txt` into that folder (`msc/src/Link/Snapshot.cs`: tab-separated text, written as `.tmp` and renamed): the key, a list of PlayMaker globals (needs, drunk, weight, fines, day and hour; not money or cigarettes, which the pocket holds), MSC's time of day (the sun's 2-hour state `MAP/SUN/Pivot/SUN :: Color`, the clock's hour state `:: Clock`, their minutes and the sun pivot's `Rotation`), the hangover (`FPSCamera/FPSCamera :: Hangover`'s state and floats; on load its `TimeLeft` runs out when the save had none, a snapshot from before it was kept included, and a saved hangover starts again from its state when MSC has none running, `msc/src/Link/Hangover.cs`), and, while MSC has the player, both vehicles (pose, velocity, fuel, whether the player sat in it) and the items `ItemLink` tracks near the player (pose, velocity, a beer case's bottle count; items in the player's hands come along with the player). Positions are Skyrim world units, so they survive a new island anchor; rotations and velocities are Unity's (the island only moves, never turns).

Loading a Skyrim save releases the player first. With a key in the cosave, Skyrim sends `MscLoad` after the load (`kPostLoadGame`; also the reload after a death). When the folder's key matches, MSC puts the globals and time of day back right away (states entered as a transition would, so the current hour runs its full length again). A save taken while MSC had the player gets Skyrim's controls back (saves taken by versions that turned them off keep them off); then, as after every load, play mode hands the player over (see [Handing over the player](#handing-over-the-player)). MSC keeps the vehicles and items until the player stands on that handover's island (30 s at most), then puts them back where they were instead of parking them next to the player; without ground there yet they are held, as when driving off the streamed area. Items are found by Unity instance id, so only within the MSC session that took the snapshot; used-up items stay gone, except beer bottles, which go back into their case. Whether the player sat in a vehicle isn't changed. A load that comes before MSC is back in its game (both games just started) waits for it, up to 3 minutes, and is applied 3 s after MSC's player shows up, so MSC's own save loading doesn't overwrite it. A save without a key (older saves, or MSC wasn't linked) or without a snapshot file leaves MSC as it is.

On every save, Skyrim removes snapshot folders whose save is gone, looking for `<name>.ess` anywhere under `Saves` (save managers keep subfolders per character), but not the one being written, nor folders changed in the last 5 minutes (`MscSave::Prune`, `protocol/cpp/msc_save.h`).

## Waiting and sleeping

T on foot opens Skyrim's own Wait menu while MSC has the player (`MenuOpenHook` lets that one key through; driving T is MSC's boost). Waiting and sleeping in a Skyrim bed (the shack's) go through the same Wait/Sleep menu. `skse/src/rest` watches the calendar: the menu opening arms `SkipTracker` (`protocol/cpp/time_skip.h`, game-free and tested) with the hours passed then and whether the player sleeps in a bed (the menu is the Sleep menu, `SleepWaitMenu::isSleeping`, since the player MSC places never lies down; or `SIT_SLEEP_STATE` want to sleep, waiting for the animation, sleeping). Once the menu has closed, frames whose clock moves more than the timescale explains (more than 0.002 h) are the skip, and when they have stopped for a second the hours since the menu opened are sent as `TimePassed` (skips under 0.05 h are dropped; a menu closed without waiting is given up on after 6 s; a load drops the tracking). Only while MSC has the player.

MSC (`msc/src/Game/RestLink.cs`, rules in `msc/src/Link/Rest.cs`, tested) uses its own bed (`...Sleep/SleepTrigger`, [FSM_MAP](FSM_MAP.md#6-needs-and-stats)): a bed sleeps 2, 4, 6, 8 or 10 hours by fatigue (under 20, 40, 60, 80, else), takes the fatigue to 0 and adds `fatigue / 5` to hunger, thirst and urine over those hours. From the fatigue at the start, per hour: fatigue `- 2 * fatigue / bedHours` in a bed (twice MSC's bed, so 8 hours take any fatigue to 0) and `- fatigue / bedHours / 2` waiting; hunger, thirst and urine `+ fatigue / 5 / bedHours` either way. Fatigue stops at 0, the needs keep rising for longer sleeps. Nothing for fatigue 0 or less. The clock moves on by the same hours: the sun (`MAP/SUN/Pivot/SUN :: Color`: the 2-hour block state, its `Time`, `Minutes`, and the pivot's `Rotation` = the block's start angle `15 * hour + 150` plus 0.5 per block minute), the display clock (`:: Clock` state `1`..`24`, `Hours`, `Minutes`) and `GlobalDay` (1..7, one per midnight the sun crosses), put back the way SaveSync does (`SaveSync.ApplyFsms`: switch the states, then the variables). Entering a block state starts its colour ease over, so the light catches up with the sun within a block.

`LoadReset` is sent at `kPreLoadGame` and `kNewGame`, before Skyrim hands the player back, whether or not the save has an MSC snapshot. MSC (`RestLink.OnLoadReset`, table in `msc/src/Link/LoadReset.cs`, tested) sends the FSMs that hold a transient action to their idle or winding-down state: `Piss :: Logic` to `State 1` (MSC's own end of the stream) or `Start urinate`, `PlayerFunctions` (push stance, finger, thumb, fist, watch, smoking) to `Initiate`, `Drink` to `State 4`, `CameraSettings` (zoom) to `Zoom out`/`Zoom out 2`, `PLAYER :: Crouch` to `Move up`; switches off the hand, cigarette and piss stream objects (`Hand Push`, `Lift`, `MiddleFinger`, `Fist`, `Watch`, `Smoking`); clears `PlayerHandLeft`, `PlayerHandRight`, `PlayerDrinkOn`, `PlayerLift`; and lets go of a carried item (`DROP_PART`, `DROP_TOOL`; a saved item comes back from the snapshot). The needs are not touched here, they come from the save (`MscLoad`, [Saves](#saves)).

## Blackouts

MSC's own blackouts (`Systems/PassOut` and `Systems/KnockOut`, [FSM_MAP](FSM_MAP.md#8-drunk-pass-out-and-knockout)) wake its player at a spawn on MSC's map, which threw Kumpo off Skyrim's map into the void. While the link is up `msc/src/Game/PassOutGuard.cs` keeps both FSMs off, and the blackout is done between the two games instead (v49):

1. MSC (`msc/src/Game/BlackoutLink.cs`, rules in `msc/src/Link/Blackout.cs`, tested) watches `PlayerDrunk` while it has the player: above 3.8 (PassOut's `Test alc`) for 10 s, or a knockout the guard had to end, blacks him out. MSC puts its player to sleep the way PassOut's `State 2` does (`PlayerSleeps` and `PlayerStop` true; MSC's `Hangover` FSM takes its strength and length from the drunk level then) and sends `Blackout` with the kind.
2. Skyrim (`skse/src/blackout/Blackout.cpp`, rules in `protocol/cpp/blackout_wake.h`, tested) takes one blackout at a time, only while MSC has the player (it reads MSC's ring only then). It fades to black over 2 s (`Game.FadeOutGame`, held black through the move by Skyrim.esm's carriage travel imagespace modifiers), then picks a map marker in Tamriel's persistent cell: an enabled one of a type on open, peaceful ground (city, town, settlement, farm, wood mill, wheat mill, stable, lighthouse, docks), at random among those at least 100,000 units (about 1.4 km) from where he fell, or among all of them when none is that far. Map markers are fast travel's destinations, so they stand on solid, reachable ground. Kumpo is moved there (`MoveTo`, no fall damage until 10 s after waking) and Skyrim's clock moves on by the blackout's hours (6 to 10 drunk, 1 to 2 knocked out, at random): `GameHour` and `GameDaysPassed`, the calendar rolls the day. With no such marker he stays where he fell, still on the anchor's ground.
3. The move is a teleport: PlayerSync sends a new anchor there and MSC puts him down once the ground has arrived ([Handing over the player](#handing-over-the-player), step 6). Once MSC's pose is placed on that anchor for 2 s (60 s at most, so the screen never stays black) Skyrim fades back in, sends `TimePassed` with `kTimeBed | kTimeBlackout` and the hours, and plays his hangover line (`IntroCue` `kIntroHangover`, captioned).
4. MSC takes the needs and the clock on by the hours as for a bed ([Waiting and sleeping](#waiting-and-sleeping)), sobers him by its own metabolism (`PlayerDrunkAdjusted` loses 0.0053 every 4 s or so, about 0.4 per MSC hour of 300 s) down to at most drunk 2.5, so he doesn't pass out again on the spot, and takes `PlayerSleeps` and `PlayerStop` off again. The hangover MSC's own FSM started shakes the camera, which Skyrim's follows.

Without Skyrim's answer in 120 s (Skyrim took the player back, a load) MSC lets him come to where he is and waits 60 s before the next blackout; `LoadReset` wakes him too. Log lines: `blackout: ...` on both sides.

## Collision chunks

Chunks are `kCollisionChunkUnits` (2048 units, about 29 m) squares on a grid anchored at world (0, 0); chunk `(x, y)` starts at `(x * 2048, y * 2048)`. A payload is the header, `vertexCount` vertices (`float[3]`, Skyrim units relative to `origin`) and `indexCount` triangle indices, then `roadCount` road triangles (`float[6]`: x, y of three corners, Skyrim units relative to `origin`, either winding). Triangles wind counterclockwise seen from outside in Skyrim (from above for the land); MSC swaps two corners per triangle because the Y/Z swap flips the handedness. A chunk with the same x/y and generation replaces the older one; chunks for another generation are dropped. A chunk has at most 65,000 vertices (Unity 5 meshes index with 16 bits); static triangles past that are left out and logged.

Skyrim side (`skse/src/collision/CollisionSampler.cpp`, `StaticMeshes.cpp`, geometry in `protocol/cpp/collision.h`): while MSC owns the player, each chunk is three parts in one payload.

- **Land**: a heightfield of 33 x 33 samples (64 units apart) from top-down Havok raycasts that keep only the landscape (the terrain or ground layer where it belongs to no reference) and pass through everything else, references on those layers too (cliffs and mountain pieces come as statics, so their overhangs stay open). A ray that misses is tried again 8 units to each side; a sample still missed with at least three hit neighbours takes their mean height, three passes over (`Collision::FillMisses`), so only wide misses leave a hole (no triangles touching it). Interiors have no land and skip this.
- **Statics**: the real collision of every loaded reference with static collision (layers static, animated static, terrain, ground, trees, stair helpers and transparent, plus clutter on bodies that don't move: buildings, walls, doors, rocks, bridges, tree trunks, interior rooms, railings, plank floors, chests), read from its Havok shapes with Havok's own body transform. Triangle meshes come as they are (walking `hkpShapeContainer` keys, so MOPP and compressed meshes need no decoding of their own); boxes and convex hulls become their faces (their vertices lie up to the hull's convex radius inside its planes; one whose planes still don't close is rebuilt from its vertices, up to 64), capsules 8-sided prisms. Shapes that carry a transform of their own (convex transform/translate, transform: planks, railings, drawbridges, doors are often boxes in these) are read with Havok 2010's layout, which CommonLib lacks, and only when that transform is a real rotation; anything else, and spheres, is skipped and counted in the log. A triangle belongs to the chunk its center is in. Loose clutter, actors, debris, water and triggers stay out. When a door opens or closes, the chunks within 256 units of it are read and sent again 1.5 s later, once it has swung. A lever-driven portcullis or a trapdoor sends no open event, so every reference with a body a script or animation moves (animated static layer or keyframed) is watched four times a second, and once it has moved and stood still for 0.3 s its chunks are read again the same way (`collision: <form id> moved and stopped`).
- **Roads**: the navmesh triangles flagged preferred (`BSNavmeshTriangle::kPreferred`, what Bethesda puts on roads for NPC pathing; deleted ones left out) of every loaded cell's navmeshes, flat (x, y only), that reach within `kRoadReach` (512 units) of the chunk. MSC uses them only to decide where road ramps go. Landscape textures would say the same but are only per 2048-unit quadrant at runtime.

The 5 x 5 chunks around the player are sampled nearest first, then the 5 x 5 around a point 2 s of travel ahead of it (at most 2 chunks ahead, so it only matters while driving), about 2 ms of raycasts per frame plus well under 1 ms to read a chunk's statics. A chunk is done once at least 99% of its land samples hit (a few always miss at cave mouths) and no static in it is still waiting for its 3D; otherwise it is sampled again every 2 s (up to 5 tries) and resent when it improves. Skyrim forgets chunks more than 3 away from both centers and MSC drops them more than 6 away from the player, so a chunk MSC dropped is always resent.

MSC side (`msc/src/Link/CollisionChunk.cs`, `msc/src/Game/PlayerLink.cs`): one `MeshCollider` per chunk under `PerkeleRim.Island`. A chunk holds land and statics in one collider, so MSC finds the ground by casting again below each hit (Unity reports one hit per collider). A player with no island surface left under its feet but one above (it stepped into a rock, whose inside is not solid, and slipped below the land) is put back within a quarter second: in a vehicle or seat on the nearest surface above; on foot where it last stood (within 25 m), and with no such spot only on a surface at most 1 m above the feet, never a ceiling or room shell meters up (`msc/src/Link/FallRescue.cs`; in dungeons the nearest-surface rule teleported the player to the ceiling). On foot, MSC remembers where the player last stood: rising faster than 30 m/s (a throw out of a wall or a hole's edge; a sprint jump is 8-13 m/s, a step-up at most 25) or falling with no island surface below for 500 m (a hole) puts it back there (`player: launched up` / `player: fell into a hole` in MSC's log). While MSC plays the player for Skyrim its controller climbs steps up to 0.5 m (MSC's own step height comes back afterwards): Skyrim's rocks and rubble are lumpier than MSC's ground. Stairs stay steps: running down them the player is snapped onto the step below (up to 0.7 m, within 0.25 s of last standing, never while rising), and the eye Skyrim's camera hangs at takes out each step steeper than 45 degrees and lets it in over about 0.12 s (`msc/src/Link/StepSmoother.cs`), so the view glides instead of bobbing. Chunks copy the layer, surface tag and physics material of MSC's asphalt (`Terrain` layer, tag `Concrete`, material `Track`): vehicle wheels only see some layers and take their grip from the surface. A new anchor clears them; the player is held at the anchor with its motor off until a chunk under it has arrived, then put down on it.

Road ramps are off (`PlayerLink.RoadRamps`, spike `island ramps on|off` rebuilds every chunk with or without them): they bumped the vehicles more than they helped and stood up as walls in gateways. When on, before building a chunk's collider MSC adds ramps over its short steps (`msc/src/Link/Fillets.cs`): the top surface sampled on a 25 cm grid, and a level deck (12 of the 25 points around it within 15 cm) 3 cm to 0.8 m above the ground next to it lays a 1 in 5 slope down from itself as extra triangles. Only on the road: a deck point lays a slope only when it and its four neighbors are inside road triangles, and a point it raises must be within 0.75 m of one. A chunk without road triangles gets no ramps.

Log lines: `collision: chunk (x,y) gen N try T: terrain hits/1089 (N on a nudged ray, N filled in, passed through N), statics N triangles from N refs (N not loaded yet, N transformed, N hulls rebuilt, N shapes skipped), roads N triangles from N navmeshes, ms + ms statics + ms navmesh` in `PerkeleRim.log`; `player: chunk (x,y) gen N: N vertices, N triangles (N ramp), N road triangles, ramps took ms, new|rebuilt`, `player: dropped N far chunks`, `player: placed on the island for gen N after S s` in MSC's log.

## Vehicles

`VehicleState` (MSC → Skyrim, one latest-value slot per vehicle since v29, vehicle id v in slot v - 1): vehicle id (`kVehicleHayosiko` 1, `kVehicleJonnez` 2, `kVehicleKekmet` 3, `kVehicleGifu` 4 since v48; `kVehicleCount` 4), flags (`kVehicleValid` while it is on the current anchor's island, `kVehicleDriven` while the player sits in it, `kVehicleSeat` while `seat` is filled), anchor `generation`, position of the vehicle's origin, rotation as a quaternion in Skyrim space (local +Y forward, +Z up), velocity, front wheel steer angle (radians, positive turns right) and each wheel's spin angle about its axle (radians in [-π, π], positive rolls forward) (Skyrim poses the wheels from `VehicleParts` since v27; these stay for whoever needs the angles; only the van's wheel names are looked up), and since v30 `seat`: where MSC's first-person camera is in the driven vehicle that same frame, in the vehicle's frame (Skyrim axes and units). `Link::WriteVehicle` picks the slot by `vehicle`, `ReadVehicle` takes the id; an id outside 1..`kVehicleCount` writes nothing and reads false.

`VehicleParts` (MSC → Skyrim, one latest-value slot per vehicle like `VehicleState`, written right after it): vehicle id, anchor `generation`, `count`, the `model` id (`ModelChunk.model`) of the vehicle's model and up to `kVehiclePartCapacity` (256) `VehiclePart`s: rotation (quaternion) and translation relative to the vehicle's body in Skyrim axes and units, and `kPartVisible` while MSC draws it. Entry `i` is node `i` of that model (v27; before, a fixed list of 40 van parts): one per MSC object of the vehicle with a mesh, so everything MSC moves or switches moves and switches in Skyrim, and the list follows from the vehicle itself. A node's pose is relative to the body, not to its MSC parent, so nesting doesn't matter on the Skyrim side.

MSC side (`msc/src/Game/VehicleLink.cs`, one instance per vehicle): each vehicle remembers where it was left in Skyrim (position, rotation, worldspace or interior cell). At a new anchor in that same space it goes back there; in another space (a load door into Dragonsreach) it is held far below the island and not sent, so Skyrim hides it, until the player is back. Snapshots keep that space too. Only the van, when never placed yet or with the garage spot, is parked next to the player as before: when the player is put down on a new anchor on foot, it is parked to its right at the first spot on its side (usual, 4 m ahead, 4 m back, 3 m further out) where the ground under its center and corners (2 m by 4.6 m around its origin; the Gifu's 2.6 m by 9.2 m) is within 0.4 m, dropped above the highest point (a rock under one corner used to throw it, sometimes into the player). The Jonnez moped, the Kekmet tractor and the Gifu truck (v48) are on call: never placed yet, they are put away like a vehicle in another space. Any of them is called by `[` (moped), `]` (van), `;` (Kekmet) or `'` (Gifu) while MSC has the player on foot: it is parked in front of the player (2.5, 6, 4.5 and 8 m ahead, facing the same way; else 3 m further ahead, or 3 m to either side, never behind), wherever it was: another worldspace, put away, or far off, and the van too if it stood at the garage's spot. From then on they follow the same rules as the van (back where they were left, kept by snapshots); calling one again brings it again. Each vehicle is dropped from 0.6 m above the ground, or 0.15 m above the height its origin stood at in MSC when that is more (the Kekmet's big wheels). A vehicle the player sits in is moved to the new anchor with the player in it and set down on its wheels at the ground there. Each gets its key if it needs one (`PlayerKeyHayosiko`, `PlayerKeyGifu`, as MSC's debug "Keys" command does). The Gifu's root is `GIFU(750/450psi)`, a name `GameObject.Find` reads as a path, so a name with a `/` is looked up among the root rigidbodies. The moped's tank is kept full (topped up once a second: MSC fills it only from a two-stroke jerry can); the van, the Kekmet and the Gifu burn their diesel ([Fuel](#fuel)). A vehicle with no island ground under it is made kinematic and keeps its velocity until the ground arrives. Every frame each writes its `VehicleState` and `VehicleParts` from its model (see below): MSC switches lights and lamps by turning objects or renderers off.

Riding the moped and the tractor on Skyrim's roads (`msc/src/Game/VehicleTune.cs`, `AirAssist.cs`, `ProgressiveSprings.cs`, `BumpSound.cs`, rules in `msc/src/Link/Righting.cs`, `Bumps.cs`, `Leaving.cs`, `Springs.cs`, `CrashMeter.cs`, all with tests): the Kekmet's suspension is MSC's 5 cm of travel on a 75000 N/m spring, which a rear wheel's 9 kN pushes 12 cm deep, so it sat on its bump stop and hopped like a solid block; it now has 30 cm of travel, 0.96x the spring and damping to match (bump 3.5x, rebound 4.5x on top of the tune's own scaling). Every vehicle also gets `ProgressiveSprings` while the vehicle is ridden (a parked moped brushed or landed on tipped over or flew off, its soft front wheels sit at 0.68 of the travel at rest, so the moped starts at 0.75, and a wheel pushes at most 3 weights): from a share of a wheel's travel (0.6, the Kekmet 0.5) the wheel pushes the body up harder with the square, up to a strength times the vehicle's weight per wheel at full travel (`Springs.Push`: van 0.5, Kekmet 0.7, moped 1.5), plus a damper on the squeeze, instead of UnityCar's bump stop. The moped balances itself like a rider only while it is within 12 degrees of the lean its turn asks for (`Righting.WantedLean`: atan(speed x yaw rate / g), at most 23 degrees, none under 2 m/s, full at 6 m/s), easing off to nothing at 30 degrees, and has two wheels on the ground; past 30 degrees it is falling and gets no help until it is within 10 degrees again, and a bike lying with all wheels off the ground gets no air assist (up axis more than 60 degrees off, or under 1.5 m/s). Kumpo can get off a tipped moped (up axis more than 45 degrees off; the van and tractor 60 degrees, `Upright.MaxTiltCos`) at any speed, and a standing one up to 1.5 m/s per axis (`VehicleTune.Settings.LeaveTipUpY`): MSC's `DriveTrigger :: PlayerTrigger` lets the player out only when every velocity axis is under its float `MinimumRequiredVelocity` (0.15), which is set every frame. Small bumps are not crashes: MSC stalls the moped when its `Starter :: Starter` FSM sees RPM under 50 in its Motor running state, so during an impact, a hop, a sideways slide (1 m/s) and 1.5 s after, the moped's engine is shielded by moving that FSM's limit below zero (setting `Drivetrain.canStall` instead made the RPM infinite and crashed MSC); an impact of 9 m/s or more (`Bumps.Stalls`, MSC kills at 12) sends `OFF` to the `Starter` FSM, stalling it as before. Collisions under 3 m/s play no crash sound (a Harmony prefix on `SoundController.OnCollisionEnter`, `BumpSound.cs`). `CrashMeter.Soften`: an impact of a vehicle on its wheels (up axis y 0.7 or more) mostly along its own up axis (0.75 or more) is a bounce and counts half, for damage and the stall alike. Vehicles are also kept safe on Skyrim's ground: the van's `TrafficTrigger` and `CarCollider` bottoms are lifted 25 cm, every body's `maxDepenetrationVelocity` is 4 m/s, a vehicle under the island is put back where it last stood on its wheels (`FallRescue.Vehicle`: within 60 m, else a surface at most 4 m above, else left alone), and one restored from a save inside the island's statics is stood upright on the nearest clear flat spot (`ClearSpot`, rings of 3 m) before it is let go.

The van's look (v27): MSC reads the running van once per link session and sends it as one model named `Hayosiko` (`msc/src/Game/VehicleModel.cs`, rules in `msc/src/Link/VanModel.cs`): every `MeshRenderer` below the van's root, switched off or not, except colliders (`coll`), the dead body, `Default-Material` submeshes and the player or items riding along. Each becomes one node straight under the model's root, at its object's pivot and rotation relative to the van, its meshes in that frame with the object's scale baked in. Glass (`WINDOWS`, `glass`, `_alpha` materials, as in `tools/nif/hayosiko.json`) is blended; the lights (`Electricity/PowerON`, the Gifu's `Electricity/Driving/DrivingLights`, `GaugesLights`, `Dashboard/Indicators/`, the Gifu's lit beacon domes `LightDomeON` and work light quads) glow at 1.5 times their texture (their `_lit` texture when the material has one). Every frame `VehicleLink` writes each node's pose and whether its renderer is on and its object active. The van is 93 objects, about 34000 vertices and 25 textures (54 MB, under the 64 MiB model limit); MSC reads it in about 2 s, Skyrim builds it in under 0.1 s. The moped and the Kekmet (v29) and the Gifu (v48) are read the same way, by the same rules, as models named `Jonnez`, `Kekmet` and `Gifu` (like `PlayerCurrentVehicle`), so their handlebar, steering, front loader, the Gifu's tank lever and hose, and their lights follow MSC as far as MSC moves those objects.

Skyrim side (`skse/src/vehicle/VehicleView.cpp`): one view per vehicle id, each vehicle's model from MSC (`ModelView::Find("Hayosiko")`, `"Jonnez"`, `"Kekmet"`, `"Gifu"`; nothing is drawn before it has arrived, and a new id from a restarted MSC is built anew), hung under the player's parent node, posed every frame from a valid `VehicleState` of the current generation in its slot. While the player drives one (whichever slot has `kVehicleDriven`) (`skse/src/player/PlayerSync.cpp`), it is hung around Skyrim's camera instead of at MSC's pose: Skyrim builds the camera before the `PlayerCharacter::Update` hook from the previous frame's placement and smooths small moves, so the van jittered and fell behind at speed. It hangs at `VehicleState.seat` from the posed camera (camera minus rotation times seat), so the controls are drawn exactly where MSC picks them, also while leaning, on the moped's wobbly head joint and with the vehicle tilted (before v30 Skyrim learned the seat while the vehicle stood still and level, and the controls twitched and drifted off the crosshair whenever the camera moved in the vehicle); the player's character controller isn't simulated while seated (like a rider). It has no reference and no Havok collision, so the collision sampler never sees it. VehicleView sets each node from `VehicleParts` (same vehicle, generation, model and node count) and app-culls the ones MSC doesn't draw, so the lights glow only while on and the wheels roll, steer and spring as MSC's do.
Vehicle lights (v35, `VehicleView::UpdateLamps`): each role that has a light on becomes a Skyrim light hung under the vehicle's node at the average place of that role's lights that are on, so light follows the vehicle. One shadow-casting spotlight for the headlights (low beam 60 degrees, 35 m; high beam 35 degrees, 57 m; one light object per role, two when a role's lights are more than 40 units apart, as the van's; the moped's beam turns with the front wheel), one shadow spotlight for the Gifu's two work lights (90 degrees, 21 m, aimed back and down over its tank), and plain point lights for the rear (tail, larger and brighter while braking), reversing, the cabin and the Gifu's beacons (one amber light for both, its brightness sweeping 1.5 times a second like a turning beacon), so at most 3 shadow lights and 4 point lights per vehicle. Skyrim renders only 4 shadow casting lights at once, torches and campfires included, so with several vehicles' headlights on near a town some drop out. A light is added to the shadow scene node when it turns on (`ShadowSceneNode::AddLight`) and removed when it turns off or the vehicle hides. The spotlight shines along the light node's local +X (Gamebryo's forward). Spike commands: `carlights` (logs every Unity `Light` of the three vehicles with type, range, intensity, place and state, plus lamp-like objects) and `lightson 1|2|0` (forces the beams, rear, reverse and cabin lights of all three vehicles on, `2` with the high beam, `0` off).

Log lines: `vehicle: found/wheel models, parks N m up/parked/waits to be called/called/got in/got out`, `vehicle model: <name> has N objects` and `surface: ...` (MSC's ground surfaces, once per game load) in MSC's log; `vehicle view: <name> model ..., N nodes`, `showing the <name>`, `<name> hidden` and `player sync: ... seated=true van shift=D` (how far the van was moved off MSC's pose to stay around the camera) in `PerkeleRim.log`. While driven, and every half second for 3 s after J righted it, MSC logs `vehicle: <name> ridden|righted N km/h, roll, pitch, center of mass, frame N ms, N kg`; `vehicle tune: <name> center of mass moved by MSC` shows MSC moving it (first 5 times). The ridden moped lands its jumps (`msc/src/Game/AirAssist.cs`): 0.15 s after all its wheels left the ground its angular velocity is eased toward turning it level and facing its flat velocity (its own heading below 2 m/s or flying backwards), logged as `air assist: landed after N s in the air`.

## Fuel

The van (40 l) and the Kekmet (65 l) burn diesel as MSC burns it (`LOD/Simulation/FuelUsage :: FuelLine`, tank `FuelTank :: Data` `FuelLevel`/`MaxCapacity`); a dry engine won't start, MSC's own doing. The moped's tank stays full (`VehicleLink.EndlessFuel`).

Four gas stations stand beside Skyrim's main roads (`tools/esp-gen`, "Gas stations"): by the garage west of Whiterun, south-east of Dragon Bridge, by the bridge below Windhelm and between Ivarstead and Riften, each a dwemer boiler (`DwePipeBoiler02`) with a gear box as the pump, open to the sky so any vehicle parks beside it, its pipes (`DwePipe1way01`) bending down into the ground (`DwePipe2way01`), and a map marker ("<place> Dwemer Oil", visible from the start). Their pump spots are persistent `XMarkerHeading`s in the `PerkeleRimFuelPumps` list (0x980); `skse/src/fuel` sends them as `FuelStations`. MSC (`msc/src/Game/FuelLink.cs`, `FuelPump.cs`, rules in `msc/src/Link/Fuel.cs`, tested):
- Within 1000 units (14 m) of a pump spot, MSC's own diesel pump trigger (`STORE/LOD/Pumps/GasolinePumpD/Functions/TriggerD`, FSM `Use`) is taken out of the store's LOD and put in front of the boiler's gear box, 1.35 m up and 0.45 m toward the boiler; it goes back to the store when Kumpo leaves. So filling up is MSC's: open the hatch (`LOD/FuelFiller/.../body_fuel_hatch/Trigger :: Use`), unscrew the cap with the scroll wheel (`FuelFiller/OpenCap :: Screw`), click the pump (PICK NOZZLE: `Pistol D` in the left hand, drawn in Skyrim through the hand layer), point it in the filler and pour; click the pump again to hang it up (DROP NOZZLE), or walk more than 6 m away and it drops (MSC's `Calculate` drops it at 3 m; its `FloatCompare` limit is raised while the trigger is away from the store, so a Kekmet parked beside the boiler can be filled). While it's at a dwemer pump its `Check hand` state's `USE` goes straight to `Activate hand`, so the store's opening hours, its pump switch and the police don't lock it.
- Gold: every litre a tank gains while Kumpo is within those 14 m costs MSC's diesel price (`TriggerD :: Use` `FuelPrice`, 3.999 marks), taken from `PlayerMoney` as it pours (Skyrim's gold follows, [The pocket](#the-pocket)); what the money doesn't cover is taken back out of the tank and the HUD says "Out of gold". Teimo's bill stays where it was: the pump's `Fuel` and the register's `Data` `DieselPurchase` are held at their values from before. A tank set by code (a snapshot, a tow, a new anchor) isn't charged.
- Towing: the call keys (`[`, `]`, `;`) call a vehicle with fuel as before. A dry one (0.25 l or less; the van stalls at 0.2 l) is called only within 2100 units (30 m) of a pump spot, for 50 gold (nothing when it already stands within 7000 units, 100 m, of the pump, `Fuel.TowFeeFrom`): it is set down in the lane beside the pump, side on, its filler next to the spot (`Fuel.TowSpot`: 134 units out from the spot, the filler's side and offset read from `LOD/FuelFiller`), with its parking brake pulled (`VehicleLink.ParkingBrake`: the van's `Dashboard/ParkingBrake :: Use` `KnobPos` to 0.1, the Kekmet's `Use` sent to `Flip` when its `Brake` is off). Elsewhere, or without the gold, the call does nothing and the HUD says why.
- The HUD's fuel line (`FuelText`, above the gear): "Dwemer oil 12.3 L, 49 gold, tank 32.1 / 40 L" while pouring and 6 s after, a 5 s message (dry, towed, no gold for the tow, out of gold), else "Fuel 8.3 / 40 L" while driving under a quarter of a tank. The van's dashboard needle shows the level too.

Log lines: `fuel: N pumps`, `fuel: the <vehicle> has L of C L` (the driven tank, at every whole litre burned), `fuel: found MSC's diesel pump, P marks a litre, register found|missing`, `fuel: MSC's diesel pump at the dwemer pump (x,y,z), ...`, `fuel: MSC's diesel pump back at the store`, `fuel: out of money at the pump, ...`, `fuel: the <vehicle> is dry, no pump within 30 m, not calling it`, `vehicle: towed the <vehicle> to (x,y,z) heading H` in MSC's log; `fuel: N pumps` and `fuel: N pumps sent to MSC` in `PerkeleRim.log`.

## Input

MSC runs hidden while Skyrim has focus, so it can't read the keyboard and mouse itself. Skyrim captures input and writes `InputState`. The MSC mod redirects every `UnityEngine.Input` call in the game's assemblies (cInput included) to a shim and answers from the latest `InputState`. `Input.mousePosition` answers with the screen center (MSC aims its look-at raycasts through the cursor, which isn't locked while its window has no focus). Details and measurements: [SPIKE_HIDDEN_MSC.md](SPIKE_HIDDEN_MSC.md).

- `keys`: 512-bit set of held Unity `KeyCode`s (mouse buttons are `Mouse0`..`Mouse6`). The shim derives Down/Up edges per MSC frame.
- `mouseX`, `mouseY`: the `Mouse X`/`Mouse Y` axes **accumulated** since Skyrim started. The two games run at different frame rates, so MSC applies the difference since its last frame; a per-frame delta would be lost or doubled.
- `mouseWheel`: the `Mouse ScrollWheel` axis, accumulated the same way (`kWheelAxisPerNotch`, 0.1 per notch, Unity's default). MSC uses the wheel for the radio dial, among others.
- `horizontal`, `vertical`: the Unity axes, -1..1.
- `flags & kInputOwnsPlayer`: MSC should apply this input at all. `flags & kInputPaused` (only with `kInputOwnsPlayer`): a Skyrim menu pauses the game (Escape, the map, inventories, not dialogue), so MSC sets `Time.timeScale` to 0.0001 (not 0: MSC's character motor divides by `Time.deltaTime`, and 0 turned the player's position into NaN) and pauses its sound (`AudioListener.pause`) until it clears, then restores its own scale (`msc/src/Link/PauseClock.cs`): nothing rolls, drains or ages behind the menu. Not with `kInputMscMenu`: MSC's own menu needs its clock (see [MSC's menu in Skyrim](#mscs-menu-in-skyrim)).
- `screenWidth`, `screenHeight`: Skyrim's back buffer in pixels, the size MSC renders its hand layer at.
- `flags & kInputMscMenu` (v47, only with `kInputOwnsPlayer`): Skyrim shows MSC's options menu (F1), see [MSC's menu in Skyrim](#mscs-menu-in-skyrim). `cursorX`, `cursorY`: Skyrim's cursor then, 0..1 of its screen from the top left (0 otherwise).

Skyrim side (`protocol/cpp/input.h`, `skse/src/player/PlayerSync.cpp`): DirectInput scan codes and mouse buttons map to Unity `KeyCode`s; Escape, Tab, `~`, F5, F9 (quicksave and quickload), F10, F11 (screenshots) and M (Skyrim's map) never reach MSC; F8 reaches it as F9 (MSC's chase camera). Mouse counts become axis units (`kMouseAxisPerCount`, 0.06 per count, Y flipped). The wheel arrives as mouse buttons 8 (up) and 9 (down), one press per notch; Skyrim's own wheel zoom refuses while MSC owns the player (see above), and so do the keyboard keys that open Skyrim's menus (P magic, J journal, I inventory, T wait, Q favorites; MSC uses them all) except Escape, Tab, M (the map) and, on foot, T (the Wait menu, see [Waiting and sleeping](#waiting-and-sleeping)); on foot R opens the Favorites menu instead of Q ([The hotbar](#the-hotbar)). While a menu has the input, keys and axes are sent empty so MSC stands still, and while it pauses the game `kInputPaused` freezes MSC's time. Every frame, keys and mouse buttons the devices no longer report as down are released, in case a release event got lost. MSC side (`msc/src/Link/InputFrame.cs`, `msc/src/Game/PlayerLink.cs`): the shim pulls the newest `InputState` before the first `Input` call of each MSC frame; the first state after a handover only seeds the mouse totals.

Running costs stamina (`protocol/cpp/stamina.h`, `PlayerSync::Sprint`; no wire change, Skyrim already owns both the stamina and the key). On foot, while Shift is held and MSC's ground speed is at least 7.5 m/s (MSC's boosted walk is about 5.5, its run about 9.6), Skyrim's stamina drops 7 a second (`DamageActorValue`, about Skyrim's own sprint cost; regen still applies, so a drunk's `StaminaRateMult` and bigger bar last longer). With the bar empty the key is held back from the `keys` sent to MSC (`Builder::Block`; Skyrim still knows it is held) until a fifth of max stamina is back, so MSC walks. Driving, Shift is the gear shift and is never held back. Log: `player sync: out of breath, MSC's run is held back` / `caught its breath, running again`.

MSC's hand actions get keys next to WASD while handed over (`msc/src/Link/KeyRemap.cs`): an alias key held becomes the key MSC's action is bound to (read from cInput, so a player's own bindings are followed), MSC's own keys keep working, and standalone MSC keeps its bindings. V, middle click, Alt (piss, on a tap: Skyrim sends it to MSC for 0.25 s only when Alt was held no longer than 0.35 s, with no other key or button pressed meanwhile and Skyrim still the window in front, so Alt+Tab never starts a stream; `protocol/cpp/piss_tap.h`), C (smoke, "cigs") and B (zoom) work everywhere, so Ctrl crouches on foot. G only on foot, since in a vehicle it is MSC's shift up (T opens Skyrim's Wait menu on foot; driving it is MSC's boost); driving, Shift and Ctrl shift gears up and down instead. Left and right click with free hands are MSC's Hit and Watch keys ([Combat](#combat)), Y and 3 to 8 the pocket ([The pocket](#the-pocket)). Keys are fixed, there is no INI. ## Handing over the player

Play mode (`protocol/cpp/play_mode.h`, tested): players never press F10. Every load (a save, a new game, the reload after a death) arms it in `PlayerSync::OnGameLoaded`, and Skyrim hands the player to MSC by itself once:

- the game has settled: 2 s of normal frames in a row (no loading screen, not paused, the player's 3D in and its cell attached; AhShitRim crashed taking the player while Skyrim was still finishing a load);
- Skyrim lets the player move (`ControlMap::IsMovementControlsEnabled`): a scene that took the controls (the Helgen cart, the execution) keeps the player;
- it's a calm moment: the player isn't in combat, on a horse, swimming, knocked down or ragdolled, sitting or lying in furniture, or in the dialogue menu (also after MSC came back from a restart). Each wait logs why (`play mode waits for the game to settle and let the player move: in combat`);
- the Helgen intro is over: while Unbound (MQ101, `0003372B`) is enabled and isn't completed, or Helgen is being skipped, nothing hands over by itself. A new game skips Helgen (`protocol/cpp/helgen_skip.h`, `skse/src/intro/HelgenSkip.cpp`): a few seconds after Kumpo's Perkele in the cart Skyrim fades to black, lets him off the cart, completes Unbound through Before the Storm's own skip stage, leaves Helgen in ruins and moves him to the garage's spawn marker, where it fades back in. Play mode then settles and hands over, and that first handover starts at the spawn marker with the van on the garage's pit (`Garage::SkippedHelgen`; no trip to the shack, no hangover line). F10 is refused while the cart's scene has the controls or while Helgen is being skipped ("Kumpo can't go over to My Summer Car until he's out of Helgen."); once the player can move in a still running Unbound, F10 hands over, the way out if it never completes. The log shows Unbound's stage and flags whenever play mode's phase changes. A save that runs Unbound without the skip (one from before it) counts as one that started in the cart (`Garage::CartStart`): its first handover starts where Kumpo stands, no trip to the shack, and the van is parked next to him as on any handover;
- MSC is linked and in its game (`kPlayerInGame`). If it isn't, Skyrim says so once per load ("My Summer Car isn't running: Kumpo stays in Skyrim until it is." or, linked but on its menu or loading, "My Summer Car is still loading: Kumpo goes over once it's in.") and hands over once MSC has been in its game for 4 s (a snapshot waiting for MSC is applied 3 s after its player shows up).

The link going down while MSC has the player ("My Summer Car is gone: Kumpo is back in Skyrim until it returns.") arms it the same way, without saying it again. F10 is a debug toggle: it takes the player back, cancels a handover play mode is still waiting for ("Kumpo stays in Skyrim (F10 hands him over)."), or hands over by hand (saying MSC isn't running when the link is down, and then handing over once it is). A handover that fails after play mode started it (the link drops on the way to the shack, the shack isn't reached in 60 s, the anchor doesn't fit in the ring) arms play mode again; after a shack trip that timed out the next handover starts where the player stands. A load that failed (`kPostLoadGame` with its success flag off) doesn't arm it. Log lines: `player sync: play mode ...`.

A new game is also Kumpo's intro: he drinks himself unconscious in MSC and wakes up in Skyrim's Helgen cart (see `IntroCue` above), then Helgen is skipped to the garage (above).

A handover (by play mode or F10) toggles who owns the player. The first handover of a save (when `PerkeleRim.esp` is loaded) first moves the player to the wake-up marker by the bed in the shack next to the garage (the garage's spawn marker after the Helgen skip, or with an ESP from before the shack); once its cell is attached Skyrim fades up from black (`MQ101FadeUpFromBlackImod`, the cart intro's), and once the player stands there the handover below runs with `kAnchorVehicleSpot` and the van marker as `vehicleSpot`, so MSC parks the van on the garage's pit instead of next to the player (on the highest ground under its wheels, so it stands on the pit's walls, not in the gap). The SKSE cosave remembers this per save, and whether the shelves were stocked (`StockShelves`, sent after the anchor of the first handover within 2048 units of the van marker). Taking over:

1. Skyrim sends `WorldspaceChange` with the player's position and heading as `spawn` (a new `generation` each time), then publishes `InputState` with `kInputOwnsPlayer`; from then on Skyrim's own input handlers for MSC's keys refuse (see Rings, input pass-through).
2. MSC drains its ring before writing a pose, so the anchor is always applied first. The anchor maps to `Island.Base` on a collision island far from MSC's map, built from `CollisionChunk`s (see above). MSC holds the player's feet at the anchor until the ground there arrives, then puts it down.
3. Every frame MSC writes `PlayerState` (feet position in Skyrim world space, velocity, heading, camera pitch, stance from the `Crouch` FSM, and the anchor `generation`). `kPlayerValid` is set only while MSC owns the player and stands on the current anchor's island. `kPlayerBlocking` is set while MSC's player guards (right click with free hands), see [Combat](#combat). With `kPlayerCamera` it also carries MSC's rendering camera: `eye` (camera minus feet, Skyrim axes and units), `roll` (positive tilts the view right) and `fov` (vertical degrees), so leaning (Q/E), reaching for the door while seated, crouching and the zoom (B while handed over) all show. With `kPlayerChaseCamera` MSC's chase camera is on (`Systems/Photomode Cam :: SwitchCamera`, MSC's F9, only in a vehicle; Skyrim's F8 reaches MSC as F9): `eye`, `roll` and `fov` are that camera's (`eye` is then metres away from the feet), and it doesn't turn with the player. `kPlayerInGame` (v41) is set every frame MSC's player exists (its game is loaded), whoever has the player; play mode hands over only then. `kPlayerMscMenu` (v47) is set while MSC's options menu is open (`PlayerInMenu` and `Systems/OptionsMenu` active), see [MSC's menu in Skyrim](#mscs-menu-in-skyrim). `kPlayerTools` (v43) is set while MSC's tools are out instead of the hand (its 2, `FPSCamera/2Spanner` active); Skyrim draws MSC's wrench and screwdriver icon top right, where MSC shows it. `throwCharge` (v46) is a throw being charged (right button held with something in the hand, `ThrowCharge.WireCharge`): 0 while not charging, else 1 plus the share of a full charge in 254 steps (255 full); Skyrim draws it as a bar just above the dot, gold once full. `viewHeading`/`viewPitch` (since v30 always, before only with the chase camera) are where the camera itself looks (its Euler yaw and pitch; with `roll` its whole rotation): seated in a rolled vehicle the player's heading and the camera's pitch missed the view by degrees looking down at the controls. With the chase camera Skyrim then puts its camera there, draws the van at MSC's pose instead of hanging it around the camera, and hides its PerkeleRim HUD. MSC cuts back to first person when Skyrim takes the player back (`msc/src/Game/ChaseCamera.cs`); MSC itself cuts back on F9 again, F1, leaving the vehicle or its own menu. While it is on MSC's mouse ray goes through the disabled first-person camera, so clicking only works again after switching back. With `kPlayerNeeds` it carries MSC's needs in `kNeed*` order: thirst, hunger, stress, urine, fatigue, dirtiness (globals `Player*`, 0..100) and drunk level (`PlayerDrunk`, 0..8).
4. Skyrim's `PlayerCharacter::Update` hook places the player at every valid pose whose `generation` is the current one (a pose with a NaN or infinite value is skipped, so a broken MSC pose can't wreck the camera) (position, heading, pitch, zeroed controller velocity) and sets sneak while the stance is crouch or prone. Skyrim has already built its first-person camera by then (from the previous frame's placement, pivoting around the head), so the hook then overrides the camera node: placed feet plus `eye`, turned to the pose's `viewHeading`, `viewPitch` and `roll` (`protocol/cpp/camera.h` keeps whatever axes Skyrim's node has on top), and sets `worldFOV` from `fov` (converted to Skyrim's horizontal-for-4:3 value; the old value comes back on release). A driven vehicle is hung around the camera by `VehicleState.seat`, so leaning moves the view inside it.
5. Skyrim draws its own HUD layer while MSC owns the player (`skse/src/hud`): a small dot at the screen center (Skyrim's crosshair is hidden then) and the latest `LookAtText` below it: a hand icon with `kLookAtUse`, the text on a dark box. MSC's needs as bars top left under Skyrim's own HUD messages (about three lines of room), clear of the inventory and map (full at 200, where MSC's player dies of a need, with a mark at 100 from where a bar turns red as MSC's own does, urine always yellow and orange from 100; the drunk bar is full at level 4, red from 2.5) with Kumpo's Money under them (Skyrim's gold, which MSC's money follows), MSC's tools icon top right while its tools are out (`kPlayerTools`), and the latest `Subtitle` on a dark box near the bottom center.
   MSC's drunk level also drives a blur with double vision (the `PerkeleRimDrunkIMAD` imagespace modifier from PerkeleRim.esp, looped), kept light since MSC itself only wobbles its camera (which Skyrim's follows) and its drunk level climbs slowly (five beers about 0.4, two dozen about 2.5): off below drunk 1.5, where MSC slurs the player's speech, then rising to strength 0.3 at drunk 4 (`skse/src/drink/Drink.cpp`).
6. If the game moves the player itself while MSC owns it (another worldspace or interior cell, or a jump of more than 2048 units: load doors, fast travel, scripts), Skyrim sends a new anchor and the island is rebuilt there.
7. MSC's own window shows what its player stands on, as a debug view (`msc/src/Game/DebugView.cs`): the island drawn, flat-shaded and colored by slope (green flat, red at 60 degrees and steeper, ramps blue, Skyrim's roads bluish green), in midday light. Only the light is midday: MSC's `MAP/SUN/Pivot/SUN :: Color` FSM also sets `GlobalHour` and `GlobalTime` when it switches hours, so instead of switching it, what it and `MAP/SUN/Pivot :: Rotation` write every frame (the sun's angle, its color, ambient and fog) is overwritten in `LateUpdate` with Color's daytime values. MSC's clock keeps running, and its own sun is back the frame after the player goes back to Skyrim. Measured on the dev machine with MSC in the background: about 104 fps with the island hidden and 112 shown, so no measurable cost.

F10 again, or the link going down, hands the player back to Skyrim (after the link went down, play mode hands over again once MSC is back).

## Screenshots

F11 in Skyrim while MSC has the player saves both games' views as one pair: `<yyyy-MM-dd_HH-mm-ss>_skyrim.png` and `..._msc.png` (`_2`, `_3` added for a second pair in the same second), in `Documents/My Games/PerkeleRim/Screenshots`. A `ScreenshotDir=<folder>` line in `Data/SKSE/Plugins/PerkeleRim.ini` overrides the folder (a relative one is under the Skyrim folder); the player launcher is meant to set it. Skyrim (`skse/src/shot`) picks the names, sends MSC its file in a `ScreenshotEvent` (`protocol/cpp/screenshot.h`, mirrored by `msc/src/Link/Screenshot.cs`) and saves its own back buffer, HUD included, in a hook on the swap chain's `Present` (installed on the first F11) as a 24-bit PNG through DirectXTK's `ScreenGrab`, then shows "Screenshot saved". MSC (`msc/src/Game/ViewShot.cs`) renders every camera that draws to its screen once more, by depth, into a texture at Skyrim's screen size and saves that at the end of the frame, so the shot is whole even with MSC's window minimized (`Application.CaptureScreenshot` reads the screen, black then). Both are logged (`shot:`). F11 never reaches MSC.

## Coordinates

On the wire everything is in **Skyrim world space**. MSC converts on its side and adds the collision island offset.

- Skyrim: X east, Y north, Z up (right-handed), game units. Heading is the Z angle in radians, 0 = north, clockwise seen from above. Pitch positive looks down.
- Unity: X east, Y up, Z north (left-handed), meters. Yaw is `eulerAngles.y` in degrees, same zero and direction.
- Scale: 1 unit = 0.0142875 m, Havok's world scale in Skyrim (69.99 units per meter).
- Positions map axis by axis (Y and Z swap, which also flips the handedness), so angles keep their sign. Results are normalized to [0, 360) degrees or [0, 2π) radians.
- One function per direction on each side (`coords.h`, `Coords.cs`), both checked against the same vectors in `protocol/tests/coords_vectors.csv`.
